## 1. 项目概述

### 1.1 背景

题阵是面向 ACM/ICPC/CCPC 等程序设计竞赛选手的学习、刷题、对战与榜单平台。平台希望通过学习路线、站内 OJ、跨平台周榜与历史总榜、1v1 对战和 AI 造数据，形成“学—练—战—榜”的训练闭环。

### 1.2 目标用户

| 用户类型 | 说明 | 核心诉求 |
|---|---|---|
| 选手 | 高校 ACM 队员、算法学习者、出题型选手 | 体系化学习、刷题反馈、对战训练、排名激励、出题提效 |
| 平台运营 | 平台内部内容运营、题库运营、用户运营 | 配置内容、维护题库、管理用户与榜单、查看操作记录 |

### 1.3 首期目标

首期交付一个**本地演示原型**，跑通“学习路线 → 刷题 → 榜单”的核心闭环，并演示对战和 AI 造数据的最小可用能力。

具体目标：

1. 选手可以使用用户名＋密码注册登录，浏览学习路线与阶段课程，完成阶段学习与练习。
2. 选手可以进行客观题、简答题和站内 OJ 编程题练习；客观题自动判分，简答题由 AI 给出分数与评语。
3. 选手可以查看全站周榜与历史总榜；周榜按自然周统计，总榜按全部历史累计，均包含站内过题和外部平台过题数据。
4. 两名选手可以通过房间邀请进行 1v1 对战。
5. 选手可以通过结构化表单选择随机生成、LLM 构造或 LLM 直接生成测试数据，并下载结果。
6. 运营可以通过最小后台维护内容、题库、用户、榜单和角色，并查看操作日志。

### 1.4 非目标

首期不做：

- 公网正式发布、ICP 备案、生产级高可用与合规。
- 多租户、外部机构后台。
- 第三方登录（微信/QQ/GitHub 等）。
- 邮箱验证码、邮箱找回密码、邮件通知；首期邮箱只做基础绑定与展示。
- 站内视频播放、课程观看进度同步、B 站账号绑定/收藏；首期课程只做外链跳转。
- 人工判分、简答题人工复核与申诉；首期简答题只做 AI 判分。
- Special Judge、交互题。
- LLM 直接生成标准程序（std）；首期 LLM 可直接生成测试数据，std 仍由选手提供。
- 随机匹配、积分/段位、观战、回放。
- 分专题周榜。
- 榜单赛季、周期重置、历史周档归档与奖励结算；总榜为全部历史累计，不设重置。
- XCPC 自建获奖数据与评分模型。
- 内容审核流、数据看板。
- 移动端 App、小程序。

## 2. 用户与角色

### 2.1 角色定义

| 角色 | 端 | 说明 |
|---|---|---|
| 选手 | C 端 | 平台主要用户，进行学习、刷题、对战、造数据、查看榜单与记录 |
| 超级管理员 | B 端 | 拥有后台全部权限 |
| 内容运营 | B 端 | 管理学习路线、阶段、阶段课程、题库、外链题；查看用户、榜单、造数据任务和操作日志；不可启用/禁用用户、不可刷新 CF 模拟数据、不可管理管理员账号 |

> 首期采用最小角色模型：超级管理员 + 内容运营。更细的角色权限后置。

### 2.2 账号体系

- 选手使用**用户名 + 密码**注册和登录；邮箱用于基础绑定与展示，首期不提供验证码、找回密码和邮件通知。
- 注册与登录在同一页面通过「登录 / 注册」页签切换；注册成功后自动登录。
- 用户名全局唯一，3–20 位字母、数字或下划线；密码至少 6 位。
- 用户名仅用于登录，昵称用于站内展示；昵称可在个人中心修改。
- 第三方登录后置。
- 运营账号由超级管理员在后台创建，使用用户名 + 密码登录；首期支持新增运营账号、启用/禁用账号和重置密码。
- 选手账号被禁用后，已登录会话立即失效，下一次操作要求重新登录；账号数据与历史成绩保留。
- 单租户：所有用户归属同一平台，不做机构/班级隔离。

### 2.3 外部账号

| 平台 | 绑定方式 | 数据获取 | 可信度标识 |
|---|---|---|---|
| Codeforces | 选手填写 handle，平台做轻量校验；原型阶段模拟校验 | 自动同步（原型阶段使用预置模拟数据，每小时刷新） | 已校验/模拟数据 |
| 其他平台（牛客等） | 选手手动申报平台、账号/主页、本周过题数 | 选手申报，超级管理员审核 | 未审核/已通过/已拒绝 |

- 一个外部平台账号只能绑定一个平台用户。
- 外部账号解绑后，历史周榜与总榜累计数据保留，但不再更新。
- 榜单页面必须标注数据来源、校验状态和更新时间。

### 3.2 原型真实度

| 能力 | 原型阶段 |
|---|---|
| 站内 OJ 判题 | 真实编译、运行、判题 |
| 客观题判分 | 真实自动判分 |
| 简答题 AI 判分 | 流程可演示；原型模拟 AI 返回 0–100 分与评语，不调用真实模型 |
| CF 绑定与校验 | 流程可演示；使用预置账号模拟校验 |
| CF 过题数据 | 预置 3–5 个演示账号 + 固定本周过题数 + 历史累计过题数；可按小时刷新 |
| 其他平台过题数据 | 选手手动申报，真实存储；超级管理员审核通过后计入榜单 |
| 历史总榜 | 预置累计数据；站内 AC、CF 刷新、手动申报后同步更新；总榜只读 |
| 对战 | 真实房间、真实判题、真实胜负判定 |
| AI 造数据 | 随机模式走通生成与下载；LLM 构造与 LLM 直接生成数据模式模拟状态与结果，不调用真实模型；LLM 凭证配置与校验为模拟流程，Key 仅保存在本机 localStorage 且脱敏展示 |
| 视频课程 | 课程数据可由后台维护；点击跳转真实 B 站链接，不内嵌播放、不同步观看状态 |
| 部署 | 本地/内网，不做公网合规 |
| 规模 | 注册 < 1 万、日活 < 1 千、同时判题 < 50 |

### 3.3 首期不做清单

见 1.4 节。首期范围之外的功能不得出现在主导航中，避免形成空功能入口。

## 4. 核心业务规则

### 4.1 内容与学习路线

| 规则 | 说明 |
|---|---|
| 内容层级 | **专题 = 学习路线 → 阶段 → 课程**。一条路线即一个专题方向；阶段挂在路线下，课程挂在阶段下 |
| 后台管理 | “专题管理”和“学习路线管理”为同一套数据，不重复建模；课程在阶段编辑中维护 |
| 题目组织 | 全局题库统一存放题目；阶段通过关联引用题目；同一题可被多个阶段复用 |
| 题目标签 | 题目至少支持：所属专题、难度、来源、题型 |
| 课程组织 | 每个阶段可关联多门课程；课程至少包含标题、B 站视频链接、时长，来源/UP 主选填 |
| 课程展示 | 路线详情展示每个阶段及其课程；阶段详情展示该阶段的视频课程列表 |
| 观看方式 | 点击课程在新标签页打开 B 站视频；平台不内嵌播放、不下载视频 |
| 链接规范 | 后台填写完整 B 站视频链接；保存时自动规范化为 `https://www.bilibili.com/video/BV...`，不接受仅填写 BV 号 |
| 课程进度 | 课程观看不计入阶段完成、学习进度或榜单；阶段完成仍由选手手动标记 |
| 阶段内容 | 图文讲解 + B 站视频课程 + 外链题 + 站内练习题 |
| 学习顺序 | 默认按阶段顺序展示，允许自由跳学，不强制解锁 |
| 完成方式 | 选手手动标记阶段完成；系统记录完成时间 |
| 首批内容 | 1–2 条路线，每条约 3–5 个阶段，每阶段约 2–3 门课程 |
| 内容来源 | 先搬运公开资料并关联公开视频链接，必须标注来源；仅用于本地演示；公网上线前替换为授权/原创内容或建立下架机制 |

### 4.2 外链题完成状态

| 场景 | 规则 |
|---|---|
| CF 题 | 选手已绑定 CF 且该题在 CF 上已 AC，系统自动标记完成 |
| 非 CF 题 | 选手手动勾选完成 |
| 未绑定 CF | 只能手动标记 |
| 完成状态用途 | 仅用于学习进度展示，不作为榜单过题口径 |

### 4.3 题库与判题

| 规则 | 说明 |
|---|---|
| 题目类型 | OJ 编程题、客观题（判断/单选/多选）、简答题、外链题 |
| OJ 语言 | C++、Python |
| OJ 题型 | 传统输入输出题；Special Judge、交互题后置 |
| 判题结果 | OJ 返回 AC、WA、TLE、MLE、RE、CE；简答题返回 0–100 分与评语 |
| 过题定义 | 题目首次 AC；同一题重复 AC 不重复计入；对战中的提交同样适用 |
| 对战提交 | 对战 AC 计入站内首次 AC，并同步计入周榜/总榜；对战非 AC 不计榜，但进入错题本 |
| 站内题来源 | 平台自建或取得授权；外部经典题只存链接与元数据 |
| 客观题判分 | 提交后立即自动判分 |
| 简答题判分 | 后台配置参考答案与评分要点；AI 按 0–100 分评分并给出评语，低于 60 分视为未通过；判分不计入榜单 |
| 错题收集 | OJ 非 AC 提交、客观题错误答案、简答题未通过自动进入错题本 |
| 题目复用 | 全局题库中的题目可被多个阶段引用 |

### 4.4 榜单（周榜 / 总榜）

周榜与总榜共用一个页面，通过顶部「周榜 / 总榜」页签切换，默认展示周榜。两种榜单共享排名表结构、我的排名卡、分页与数据来源标注规则。

**周榜规则**

| 规则 | 说明 |
|---|---|
| 榜单范围 | 全站周榜；首期不做分专题榜 |
| 站内过题 | 仅统计站内 OJ 编程题的本周首次 AC（含对战）；客观题、简答题、重复 AC 不计入 |
| 站内去重 | 同一题在本周内只计一次；若该题在更早周已 AC，本周不再计入 |
| 对战提交 | 对战中的 OJ 提交按同一首次 AC 口径计入；非 AC 不计入榜单，但进入错题本 |
| 禁用用户 | 被禁用用户不参与排名与展示；重新启用后恢复展示，历史数据保留 |
| 题目下架 | 已下架题目的历史 AC 仍计入，不回溯扣减 |
| 外部数据 | CF 自动同步（原型模拟，每小时刷新）；其他平台手动申报 |
| CF 校验 | 选手在 CF 个人资料放置平台验证码；原型阶段用预置账号模拟校验 |
| 其他平台校验 | 选手申报后由超级管理员审核；仅审核通过计入榜单，未审核或已拒绝不计分 |
| 手动申报唯一性 | 同一用户＋同一平台＋同一自然周只保留一条；重复提交覆盖原记录，不累加，覆盖后需重新审核 |
| 手动申报审核 | 超级管理员可在后台通过或拒绝；内容运营只读；审核结果可改判，改判后榜单实时变化 |
| 周口径 | 北京时间自然周：周一 00:00 至周日 24:00 |
| 计入范围 | 比赛题与赛后补题都计入；外部数据按平台内题目去重 |
| 跨平台去重 | 首期不做；同一题在不同平台分别计数 |
| 更新频率 | 站内 AC 实时更新；CF 数据每小时同步；手动申报审核通过后更新 |
| 排名规则 | 总分 = 站内过题 + 外部过题；总分相同按站内过题数降序，仍相同并列 |
| 奖励 | 不设物质奖励 |
| 展示范围 | 前 20 名 + 我的排名；支持查看更多/分页 |
| 展示信息 | 排名、选手、站内过题、CF 过题、手动申报过题、总分、数据来源、更新时间 |

**总榜规则**

| 规则 | 说明 |
|---|---|
| 榜单定位 | 全部历史累计排名，用于展示选手长期训练产出；与周榜并列，不替代周榜 |
| 统计区间 | 自平台上线起至当前，不设赛季、周期重置或清零 |
| 站内过题 | 站内 OJ 编程题的历史首次 AC（含对战提交）；同一题只计一次，客观题、简答题、重复 AC 不计入 |
| CF 过题 | 绑定 CF 账号的历史总过题数（原型使用预置累计值）；不按周汇总累加 |
| 手动申报 | 历史各周审核通过的手动申报过题数累计；同一用户＋同一平台＋同一自然周只保留一条；未审核或已拒绝不计分 |
| 手动申报入口 | 仅周榜提供本周申报入口；总榜只读，不提供总榜申报 |
| 跨平台去重 | 首期不做；同一题在不同平台分别计数 |
| 禁用用户 | 被禁用用户不参与排名与展示；重新启用后恢复展示，历史数据保留 |
| 题目下架 | 已下架题目的历史 AC 仍计入，不回溯扣减 |
| 更新频率 | 站内 AC 实时累加；CF 刷新后更新历史累计；手动申报审核通过后累加 |
| 排名规则 | 总分 = 站内累计 + CF 累计 + 手动申报累计；总分相同按站内累计降序，仍相同并列 |
| 展示范围 | 前 20 名 + 我的排名；支持查看更多/分页 |
| 展示信息 | 排名、选手、站内累计、CF 累计、手动申报累计、总分、数据来源、更新时间 |

### 4.5 对战

| 规则 | 说明 |
|---|---|
| 对战形式 | 房间邀请制，两名选手；不做随机匹配 |
| 房间创建 | 选手选择难度/专题筛选条件，创建房间并生成邀请码/邀请链接 |
| 加入房间 | 另一名选手通过邀请码/链接加入；房间满两人后准备 |
| 题目来源 | 全局题库随机抽取一道符合筛选条件的传统题 |
| 开始条件 | 双方准备后同时开始，双方看到同一道题 |
| 单局时限 | 30 分钟 |
| 胜负判定 | 先 AC 者胜；超时无人 AC 判平局；中途主动退出判负 |
| 对战提交 | 对战 AC 计入站内首次 AC，并同步计入周榜/总榜；非 AC 进入错题本 |
| 断线处理 | 断线立即判负，不设重连等待 |
| 不做能力 | 随机匹配、积分/段位、观战、回放、代码互看 |
| 对战记录 | 列表 + 详情：对手、题目、双方提交状态、最终结果、开始/结束时间 |

### 4.6 AI 造数据

| 规则 | 说明 |
|---|---|
| 输入方式 | 结构化表单 + 可选自然语言要求 |
| 表单字段 | 题目名称、题面、输入格式、输出格式、std 代码、数据范围、生成组数、时限/内存；LLM 模式（构造/直接生成）增加「特殊构造要求」（选填） |
| 调用密钥 | LLM 构造与 LLM 直接生成数据使用选手本人的 API Key，调用费用由选手承担；随机生成不需要 Key |
| 密钥适用范围 | 个人 Key 仅用于 LLM 造数据；简答题 AI 判分仍使用平台密钥，不要求选手配置 Key |
| 服务商范围 | 选手从后台预置的服务商列表中选择并填写对应 Key；平台只请求预置地址，不接受自定义 Base URL |
| 凭证形式 | 每位选手保留一份有效凭证（服务商 + API Key + 可选模型）；服务端加密保存，接口只返回脱敏信息，不回显明文；可替换、删除 |
| 凭证校验 | 保存时调用服务商轻量接口验证；创建任务时复检；执行中 Key 失效、欠费、超时或服务商错误时任务失败并给出原因 |
| 使用约束 | 未配置有效凭证时，两种 LLM 模式禁用并引导配置；同一选手同时最多 1 个进行中的 LLM 造数据任务；凭证在任务进行中不可删除或替换 |
| 数据范围 | 按变量定义类型、最小值、最大值及必要约束 |
| 生成方式 | 三种模式：**随机生成**（默认）、**LLM 构造**与 **LLM 直接生成数据**。LLM 构造由 LLM 生成数据构造器（generator），平台运行构造器产出输入；LLM 直接生成由 LLM 按题面、输入输出格式、数据范围、组数与特殊要求直接产出输入文件 |
| 生成器可见性 | 仅 LLM 构造模式产生生成器代码；生成器代码不向选手展示，平台内部保留用于执行与排错，不提供下载 |
| 答案来源 | std 始终由用户提供；平台对每组输入运行 std 生成对应输出，LLM 不生成 std |
| 生成组数 | 默认 10 组，允许在合理范围内调整 |
| 校验信息 | LLM 构造状态、LLM 数据生成状态、生成器执行状态、std 运行结果、格式/范围校验、运行时间、文件大小、失败原因 |
| 产出形式 | 输入/输出文件打包下载；三种模式的产出形式一致 |
| 不支持 | Special Judge、交互题；LLM 直接生成 std |
| 任务状态 | 待生成、LLM 构造中（仅 LLM 构造）、LLM 生成数据中（仅 LLM 直接生成）、生成中、成功、失败 |
| 失败处理 | LLM 调用失败/超时、Key 无效/欠费/过期、生成器无法执行、LLM 直接生成的数据不符合格式/范围、std 运行失败时任务终止，展示失败原因；不支持自动重试；选手更新凭证后可手动重新提交 |
| 数据出境提示 | 提交 LLM 任务时明确提示：题面、输入输出格式、数据范围与特殊要求会发送给所选第三方服务商 |
| 文件保留 | 输入/输出文件保留 7 天，到期自动清理；任务记录、参数、状态和失败原因保留，不随文件清理删除 |
| 安全要求 | 生成器与 std 代码必须在隔离环境中执行，限制 CPU、内存、运行时间和文件访问；LLM 输出（构造器或直接生成的数据）视为不可信输入，直接生成的数据需逐组校验格式与范围 |
| 任务记录 | 列表 + 详情 + 下载；后台提供列表 + 详情查看 |

## 5. 功能需求

### 5.1 注册登录与个人中心

**目标**：让选手完成账号注册、登录、资料维护和外部账号绑定。

**功能点**

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| U-01 | 用户名密码登录 | 用户名 + 密码；用户名大小写不敏感；错误提示统一为“用户名或密码错误” | P0 |
| U-02 | 账号注册 | 用户名、昵称、密码、确认密码；注册成功后自动登录 | P0 |
| U-03 | 邮箱绑定 | 基础绑定与展示；首期不含验证码、找回密码和邮件通知 | P0 |
| U-04 | 个人资料 | 查看/编辑昵称、头像、学校（可选） | P1 |
| U-05 | CF 绑定 | 输入 CF handle；原型模拟校验；显示绑定状态 | P0 |
| U-06 | CF 解绑 | 解除绑定；历史数据保留 | P1 |
| U-07 | 其他平台申报 | 填写平台、账号/主页、本周过题数；提交后待超级管理员审核；可修改/删除 | P0 |
| U-08 | 退出登录 | 清除登录状态 | P0 |
| U-09 | LLM API Key 凭证 | 个人中心配置服务商、API Key 与可选模型；保存时校验，脱敏展示，可替换/删除；仅用于 LLM 造数据 | P0 |

**业务规则**

- 用户名全局唯一，3–20 位字母、数字或下划线；密码至少 6 位；两次密码必须一致。
- 用户名仅用于登录，昵称用于站内展示；昵称可在个人中心修改。
- 密码需加密存储，任何页面不展示明文密码。
- 一个 CF handle 只能绑定一个平台用户。
- 其他平台申报按自然周存储；跨周需重新申报或更新。
- 同一用户＋同一平台＋同一自然周的手动申报只保留一条，重复提交覆盖原记录；覆盖后审核状态重置为未审核，需超级管理员重新审核。
- 手动申报由超级管理员审核通过后方可计入周榜/总榜；未审核或已拒绝不计分，审核备注仅后台可见。
- 所有外部账号信息在榜单中标注来源与校验状态。
- 邮箱只做基础绑定与展示；首期不提供验证码、找回密码和邮件通知。
- 每位选手最多保存一份 LLM 凭证，包含服务商、API Key 与可选模型；服务商来自后台预置列表，不支持自定义 Base URL。
- API Key 仅用于服务端调用 LLM 造数据，保存后不再回显明文；页面只展示脱敏尾号、服务商、状态与最近校验时间。
- 保存凭证时校验 Key 可用性；校验失败不保存并提示原因。凭证可在任务结束后替换或删除；存在进行中的 LLM 造数据任务时禁止替换或删除。
- 选手可自行删除凭证；删除后两种 LLM 造数据模式不可提交，随机模式不受影响。
- 运营后台仅可查看选手凭证的配置状态、服务商、最近校验结果与时间，不可查看 Key 明文或尾号，不提供代填。
- 运营账号由超级管理员创建，使用用户名 + 密码登录，不开放注册；超级管理员可新增运营账号、启用/禁用账号和重置密码。
- 选手账号被禁用后，已登录会话立即失效，下一次操作要求重新登录；账号数据与历史成绩保留。

**验收标准**

- 新用户可用用户名＋密码完成注册并自动登录。
- 重复用户名、格式不合法的用户名、少于 6 位的密码、两次密码不一致均被拦截并给出提示。
- 使用错误密码登录被拒绝；禁用账号无法登录。
- 绑定邮箱后可正常展示；资料修改后刷新仍生效。
- 预置 CF handle 绑定成功并显示“已校验/模拟数据”；非法 handle 显示失败原因。
- 其他平台申报后显示“未审核”，榜单不计分；超级管理员审核通过后，周榜出现对应外部过题数、总榜手动累计同步增加；同一周重复申报时覆盖而非累加，并需重新审核。
- 账号被禁用后，已登录会话在下一次操作时失效并要求重新登录。
- 选手可保存一份有效的 LLM 凭证，保存成功后仅展示脱敏尾号与服务商；无效 Key 被拒绝保存并给出原因。
- 删除凭证后，造数据页的两种 LLM 模式不可提交并展示配置引导；重新配置有效凭证后恢复。
- 任务进行中尝试替换或删除凭证被阻止；任务结束后可正常替换或删除。

**功能点**

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| R-01 | 路线列表 | 展示路线名称、简介、阶段数、学习进度 | P0 |
| R-02 | 路线详情 | 展示阶段列表、推荐顺序、完成状态，以及每个阶段下的视频课程 | P0 |
| R-03 | 阶段详情 | 展示图文内容、视频课程、外链题、站内练习题 | P0 |

**验收标准**

- 选手可浏览路线和阶段，完成状态可保存。
- 路线详情中每个阶段可看到课程清单；阶段详情中可看到完整课程列表。

- 阶段内的外链题可跳转，站内练习题可进入做题页。
- 绑定 CF 的选手在完成 CF 题后可看到自动完成标记；非 CF 题可手动标记。
- 路线进度百分比仅随阶段完成状态变化；外链题完成单独展示，不影响百分比。

### 5.4 题库与刷题

**目标**：提供客观题、简答题和 OJ 编程题练习，并给出判题/判分结果。

**功能点**

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| P-01 | 题库列表 | 按专题、难度、题型、来源筛选；标题搜索 | P0 |
| P-02 | 题目详情 | 展示题面、输入输出格式、样例、限制 | P0 |
| P-03 | 客观题作答 | 判断/单选/多选；提交后自动判分 | P0 |
| P-04 | OJ 作答 | 代码编辑器、语言切换（C++/Python）、提交 | P0 |
| P-05 | 判题结果 | OJ 展示 AC/WA/TLE/MLE/RE/CE 及运行信息；简答题展示 0–100 分与评语 | P0 |
| P-06 | 提交历史 | 查看本人该题的提交记录 | P1 |
| P-07 | 错题自动收集 | OJ 非 AC、客观题错误答案、简答题未通过自动进入错题本 | P1 |
| P-08 | 简答题作答与 AI 判分 | 文本作答；提交后由 AI 给出 0–100 分与评语；低于 60 分进入错题本 | P1 |

**业务规则**

- OJ 题目必须配置测试数据、时限、内存限制。
- 客观题必须配置正确答案；多选题支持多个正确选项。
- 客观题提交后立即返回判定结果，并展示正确答案；解析字段可选，由后台填写。
- 简答题必须配置参考答案与评分要点；AI 按 0–100 分评分并返回评语，低于 60 分视为未通过。
- 简答题提交后进入 AI 判分，页面展示「判分中」；判分完成后展示分数与评语，判分失败时提示原因并允许重新提交，不自动重试。
- 简答题不计入榜单；未通过时进入错题本，再次通过不自动移除。
- OJ 首次 AC 才计入榜单；周榜按本周首次 AC，总榜按历史首次 AC；重复 AC 不计入；对战中的 AC 按同一口径计入。
- 对战中的非 AC 提交同样进入错题本，但不计入榜单。
- 已下架题目的历史 AC 仍保留在周榜/总榜中，不回溯扣减。
- 题目可同时属于多个阶段。

**验收标准**

- 选手可筛选并打开题目，客观题提交后得到正确/错误结果。
- C++/Python 代码可提交并返回判题结果。
- 简答题提交后展示判分中状态，完成后展示 0–100 分与评语；低于 60 分进入错题本，且不计入榜单。
- AI 判分失败时展示失败原因，选手可重新提交。
- 错误提交进入错题本。
- 首次 AC 后，周榜与总榜站内过题数同步增加；对战中的首次 AC 同样生效。
- 题目下架后，其历史 AC 仍计入周榜与总榜，不回溯扣减。

### 5.5 榜单（周榜 / 总榜）

**目标**：展示全站选手的短期（本周）与长期（全部历史）过题排名，聚合站内与外部平台数据。

**功能点**

| L-02 | 我的排名 | 展示当前榜单下自己的排名与各项过题数 | P0 |
| L-03 | 数据来源标注 | 标注站内/CF/手动申报、校验状态、更新时间 | P0 |
| L-04 | 手动申报入口 | 填写其他平台本周过题数；仅周榜提供；同周同平台重复提交覆盖；提交后待审核 | P0 |

**业务规则**

- 站内仅统计 OJ 首次 AC，含对战中的首次 AC；客观题、重复 AC 不计入；周榜按本周首次 AC，总榜按历史首次 AC。
- 被禁用用户不参与排名与展示；重新启用后恢复展示，历史成绩保留。
- 已下架题目的历史 AC 仍计入周榜/总榜，不回溯扣减。
- 外部数据：CF 自动同步；其他平台手动申报，由超级管理员审核。
- 同一用户＋同一平台＋同一自然周的手动申报只保留一条，重复提交覆盖原记录；总榜按各周审核通过的记录累计。
- 手动申报仅审核通过后计入周榜/总榜；未审核或已拒绝不计分，审核结果可改判。
- 总榜 CF 取账号历史总过题数，不按周汇总累加；手动申报按历史各周审核通过的记录累计。
- 平台内去重；跨平台不去重。
- 周榜与总榜均按“总分相同则站内过题数降序，仍相同并列”排名。
- 总榜只读，不提供总榜手动申报入口；手动申报仍按周在周榜入口提交。
- 不设物质奖励。
- 榜单必须标注数据来源、校验状态和更新时间。

**验收标准**

- 周榜正确展示演示账号的站内、CF、手动申报数据。
- 总榜正确展示演示账号的站内累计、CF 累计、手动申报累计数据，且总分与排名正确。
- 周榜与总榜可切换，切换后我的排名、表格、统计口径说明同步更新。
- 站内 AC 后周榜与总榜同步更新；对战中的首次 AC 同样使两榜更新。
- 手动申报提交后显示“未审核”且榜单不计分；超级管理员审核通过后周榜更新、总榜手动累计同步增加；拒绝或改判后榜单实时变化；同一周重复申报时覆盖原记录并重置审核状态。
- 被禁用用户从周榜/总榜移出；重新启用后恢复展示，历史成绩不变。
- 已下架题目的历史 AC 仍计入周榜/总榜，不回溯扣减。
- 榜单默认展示前 20 名与我的排名，点击查看更多可按页加载后续排名。

### 5.7 AI 造数据

**目标**：让选手以出题人身份，通过结构化表单与可选自然语言要求生成测试数据；既支持稳定的随机生成，也支持由 LLM 构造数据构造器或直接生成测试数据。

**功能点**

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| D-01 | 造数据表单 | 模式选择、题面、std、数据范围、组数、限制；LLM 模式支持特殊构造要求 | P0 |
| D-02 | 生成方式 | 随机生成（默认）/ LLM 构造 / LLM 直接生成数据；切换不丢失已填表单内容 | P0 |
| D-03 | 提交任务 | 创建生成任务，异步执行；LLM 构造先构造生成器，LLM 直接生成先产出输入数据 | P0 |
| D-04 | 任务状态 | 待生成 / LLM 构造中 / LLM 生成数据中 / 生成中 / 成功 / 失败 | P0 |
| D-05 | 结果详情 | 生成文件、校验信息、失败原因；不展示生成器代码（直接生成模式无生成器） | P0 |
| D-06 | 文件下载 | 输入/输出文件打包下载 | P0 |
| D-07 | 任务记录 | 列表 + 详情 + 下载；列表标注生成方式 | P1 |
| D-08 | LLM 直接生成数据 | 由 LLM 直接产出约 10 组输入文件；平台校验后运行用户 std 产出输出 | P1 |
| D-09 | LLM 凭证约束 | LLM 模式使用选手自带 Key；未配置禁用并引导；任务创建前复检、执行中失效即失败；每人最多 1 个进行中 LLM 任务 | P0 |

**业务规则**

- 造数据提供三种模式：随机生成（默认）、LLM 构造与 LLM 直接生成数据；三种模式都要求用户提供 std。
- LLM 构造与 LLM 直接生成数据使用选手本人的 API Key，费用由选手承担；随机生成不需要 Key。
- 个人 Key 仅用于 LLM 造数据；简答题 AI 判分继续使用平台密钥，不要求选手配置 Key。
- 选手从后台预置的服务商列表中选择，并填写对应 API Key 与可选模型；平台只请求预置地址，不接受自定义 Base URL。
- 未配置有效凭证时，两种 LLM 模式禁用并引导选手到个人中心配置；随机模式不受影响。
- 创建 LLM 任务时复检凭证；存在进行中的 LLM 任务时禁止再次提交（同一选手最多 1 个进行中 LLM 任务）。
- LLM 任务进行中禁止替换或删除凭证；任务结束后可修改。
- 凭证明文不得下发浏览器；个人中心与接口只展示脱敏尾号、服务商、状态与最近校验时间；运营后台仅可查看配置状态、服务商与最近校验结果，不可查看 Key 明文或尾号。
- LLM 构造模式将题面、输入格式、输出格式、数据范围、组数、时限/内存与「特殊构造要求」作为上下文，生成数据构造器代码。
- LLM 直接生成数据模式将同样的上下文直接交给 LLM，由 LLM 产出输入文件；不生成数据构造器，也不生成 std。
- 平台对 LLM 直接生成的数据逐组校验输入格式与数据范围；校验通过后运行 std 生成对应输出。
- 生成器代码仅在 LLM 构造模式产生，不向选手展示、不提供下载；页面只展示构造/生成状态与最终文件。
- 「特殊构造要求」为选填自然语言，例如「包含全相同元素、链状图、卡精度数据」；不承诺逐条命中，生成结果需用户自行校验。
- 默认生成 10 组数据，允许在合理范围内调整。
- std 必须成功运行才能产出对应输出；任一组失败时任务标记失败并给出原因。
- LLM 调用失败/超时、Key 无效/欠费/过期、生成器无法执行、LLM 直接生成的数据不符合格式/范围或 std 运行失败时，任务终止并给出原因。
- 任务失败或超时后终止，展示失败原因；不支持自动重试；选手更新凭证后可手动重新提交。
- 提交 LLM 任务时明确提示：题面、输入输出格式、数据范围与特殊要求会发送给所选第三方服务商。
- 输入/输出文件保留 7 天，到期自动清理；任务记录、参数、状态和失败原因保留，不随文件清理删除。
- 生成器与 std 均在隔离环境中执行，限制 CPU、内存、运行时间和文件访问；LLM 输出（构造器或直接生成的数据）视为不可信输入。
- 生成结果只对创建者和管理员可见。

**验收标准**

- 选手可在随机生成、LLM 构造与 LLM 直接生成数据之间切换，默认选中随机生成。
- 未配置有效 LLM 凭证时，两种 LLM 模式不可提交，页面展示配置引导；配置有效凭证后恢复。
- 选手可保存、替换、删除 LLM 凭证；保存无效 Key 被拒绝并提示原因；页面不展示 Key 明文。
- 同一选手已有进行中的 LLM 任务时，再次提交被阻止并提示；任务结束后可再次提交。
- 任务进行中尝试替换或删除凭证被阻止。
- LLM 任务执行中 Key 失效、欠费或超时，任务失败并展示原因，不自动重试。
- 随机模式可正常提交并生成约 10 组输入/输出文件。
- LLM 构造模式提交后展示「LLM 构造中 → 生成中」状态，成功后生成约 10 组文件，可下载。
- LLM 直接生成模式提交后展示「LLM 生成数据中 → 生成中」状态，成功后生成约 10 组文件，可下载。
- 页面不展示 LLM 生成的数据构造器代码；直接生成模式不产生生成器。
- 校验信息展示生成状态、std 运行情况、格式/范围校验、文件大小等。
- LLM 直接生成的数据不符合格式/范围时，任务失败并给出原因。
- 失败任务展示失败原因，且不会自动重试。
- 文件到期清理后，任务记录仍可查看参数、状态和失败原因。
- 后台可查看任务列表与详情，并能区分三种生成方式；后台用户详情可查看选手凭证是否已配置、服务商与最近校验结果，不显示 Key 明文或尾号。

- 可在阶段编辑中新增/编辑/删除课程，保存后 C 端路线详情与阶段详情同步更新。
- 填写非法 B 站链接时保存被拦截，并给出明确提示。
- 超级管理员可查看用户列表、启用/禁用用户；内容运营只能查看，不能启用/禁用。
- 用户详情可看到 LLM 凭证是否已配置、服务商与最近校验结果，不显示 Key 明文或尾号。

**关键关系**

- Route 1:N Stage。
- Stage 1:N Course。
- Stage N:M Problem（通过 StageProblem）。
- Problem 1:N TestData / ObjectiveOption。
- User 1:N Submission、LearningProgress、WrongBook、ExternalAccount、ManualDeclaration、DataGenTask。
- User 1:1 UserLlmCredential；DataGenTask N:1 UserLlmCredential（LLM 模式记录凭证引用，不复制 Key 明文）。
- BattleRoom N:1 Problem；BattleRoom N:2 User（创建者/对手）。
- DataGenTask 1:N DataGenFile。
- AdminUser N:1 Role；OperationLog N:1 AdminUser。

> 周榜与总榜均为派生统计视图，不单独存储榜单快照：周榜取本周首次 AC、CF 周数据与本周手动申报；总榜取历史首次 AC、CF 历史累计与全部周手动申报之和。

> 外链题完成状态、对战记录与 CF 周数据的持久化实体及关系，在数据库设计阶段补充。简答题评分配置、LLM 直接生成状态与选手 LLM 凭证已在 Problem、Submission、DataGenTask、UserLlmCredential 中以字段体现，最终表结构以数据库设计为准。

## 8. 非功能需求

### 8.1 部署与规模

| 项目 | 首期要求 |
|---|---|
| 部署 | 本地/内网演示，不要求公网 |
| 规模 | 注册 < 1 万、日活 < 1 千、同时判题 < 50 |
| 数据持久化 | 用户、题目、提交、记录、任务等数据需持久化 |
| 备份 | 本地演示阶段建议定期备份数据库与生成文件 |

### 8.2 性能

- OJ 判题应在可接受时间内返回结果；原型阶段建议普通题目数秒内返回。
- 榜单页面（周榜 / 总榜）应在正常数据量下快速加载，默认前 20 名，分页加载后续排名；具体指标在详细设计中确认。
- 造数据任务异步执行，页面不阻塞等待；LLM 构造与 LLM 直接生成数据阶段应有超时控制与明确状态。
- 简答题 AI 判分不阻塞页面；判分中展示明确状态，超时或失败时提示原因并允许重新提交。

### 8.3 安全

- OJ 提交代码必须在隔离环境中编译和运行，限制 CPU、内存、运行时间和文件访问。
- 造数据任务中的生成器与 std 代码同样必须隔离执行。
- LLM 输出视为不可信输入：生成的构造器不得访问宿主机文件、网络和敏感信息；LLM 直接生成的测试数据必须逐组校验格式与范围；平台需限制其运行时间与资源。
- 简答题文本、AI 评分提示词与评语均按不可信内容处理；评语展示需转义，避免提示注入或脚本注入。
- 平台 LLM 密钥（简答判分）仅保存在服务端，不得下发到浏览器；选手输入不得直接拼接为可执行系统命令。
- 选手 LLM API Key 必须服务端加密保存，密钥原文仅在调用服务商时解密使用；接口、页面、日志、异常信息均不得回显明文或完整 Key，页面只展示脱敏尾号。
- 选手凭证仅允许用于后台预置的服务商地址，禁止使用自定义 Base URL，避免服务端被用于请求任意地址（SSRF）。
- 选手删除或替换凭证时清理旧密文；存在进行中的 LLM 任务时禁止删除或替换。
- 运营后台只能查看凭证配置状态、服务商与最近校验结果，不得查看或代填 Key。
- 禁止选手代码访问宿主机文件、网络和敏感信息。
- 管理员操作需鉴权；操作日志不可被普通用户访问。
- 选手密码必须加盐哈希存储，登录接口需限制暴力尝试频次；任何接口和日志不得返回明文密码。
- 手机号、邮箱等个人信息仅用于账号绑定与展示，公网上线前需补充隐私政策。

### 8.4 合规与版权

- 首期为本地演示，不对外公开，暂不要求 ICP 备案。
- 搬运的公开资料必须标注来源，仅用于本地演示。
- 课程只保存 B 站视频链接并做外链跳转，不下载、不转存、不内嵌播放视频内容。
- 公网上线前需确认课程视频的授权/引用合规性，并建立失效链接巡检与下架机制。
- 公网上线前需完成：内容授权/替换、下架机制、隐私政策、用户协议、ICP 备案、内容安全审核。

### 8.5 可维护性

- 题目、路线、阶段、课程等内容通过后台配置，不写死在代码中。
- 判题结果、造数据任务状态、操作日志需可查询。
- 外部平台数据来源需可追溯，便于后续接入真实接口。

### 10.3 风险提示

| 风险 | 说明 | 应对 |
|---|---|---|
| 断线立即判负误伤 | 网络波动可能导致误判 | 演示环境尽量稳定；上线前可评估重连机制 |

| 总榜手动申报重复累计 | 同一周内重复申报已覆盖，但同一批题跨周重复申报时总榜仍会重复计入 | 仅审核通过记录累计，后台展示累计申报；后续接入平台接口后按题目去重 |
| 内容版权 | 搬运资料仅限本地演示 | 公网上线前替换/授权/建立下架机制 |
| 生成文件存储 | 输入/输出文件保留 7 天，过期清理；任务记录保留 | 演示前确认关键文件已下载备份 |
| LLM 生成质量不稳定 | 生成器可能无法执行，直接生成的数据可能不满足格式/范围，且不可复现 | std 作为唯一答案来源；数据逐组校验；失败终止并给出原因；生成结果由用户自行校验 |
| LLM 调用时延与成本 | LLM 构造/直接生成阶段比随机模式更慢，可能受模型服务波动影响 | 异步任务 + 超时终止；页面明确展示「LLM 构造中」或「LLM 生成数据中」状态 |
| LLM 输出安全 | 生成器可能包含危险操作，直接生成的数据可能包含异常内容 | 生成器隔离运行，限制网络、文件与资源；直接生成数据逐组校验；平台密钥与选手凭证均只在服务端使用 |
| 选手 Key 泄露 | 选手 Key 可能通过接口、日志、异常信息或前端缓存泄露 | 服务端加密保存；接口只返回脱敏信息；日志与异常脱敏；页面不回显完整 Key；上线前做密钥泄露检查 |
| 选手 Key 失效/欠费 | Key 过期、余额不足或服务商限流会导致任务失败 | 保存时校验、执行前复检；失败终止并明确提示；选手更新凭证后手动重提 |
| 第三方数据出境 | 题面、特殊要求等会发送给所选服务商 | 提交前明确提示；仅发送造数据所需内容；在隐私政策中说明第三方处理 |
| 服务商差异 | 不同预置服务商的模型能力、响应格式与限流不同 | 仅接入 OpenAI 兼容的预置服务商；统一提示词与响应解析；允许可选模型并记录实际使用模型 |
| 简答题 AI 判分偏差 | AI 评分可能受表述、提示词或模型波动影响，与人工判断不一致 | 配置明确的参考答案与评分要点；展示分数与评语供选手参考；后续可评估人工复核/申诉 |
| 简答题提示注入 | 选手答案可能试图操纵 AI 评分或评语 | 答案按不可信输入处理；评分提示词与密钥仅在服务端；评语展示转义 |
| B 站链接失效 | 视频可能被删除、下架或改为分 P | 后台保存规范化链接；上线前增加链接巡检与失效提示 |
| 课程版权 | 外链视频版权归原作者/平台 | 仅做跳转不转存；标注来源；公网上线前确认引用合规 |
| 密码安全 | 原型 localStorage 使用明文演示数据 | 正式环境使用加盐哈希、限流与找回流程；原型明确标注仅用于演示 |
| 邮箱未验证 | 首期邮箱只做基础绑定，不验证归属 | 仅用于展示；公网上线前补充验证、找回密码与通知能力 |

| DEC-74 | LLM 任务并发 | 同一选手同时最多 1 个进行中的 LLM 造数据任务；任务进行中禁止替换/删除凭证 | 本次需求变更 |
| DEC-75 | 凭证后台可见性 | 运营后台仅可查看配置状态、服务商与最近校验结果，不可查看 Key 明文或尾号，不提供代填 | 本次需求变更 |
| DEC-76 | 手动申报审核 | 超级管理员可通过或拒绝手动申报，内容运营只读；仅审核通过计入周榜/总榜；支持改判；拒绝原因选填（≤ 200 字），仅后台可见 | 本次需求变更 |

## 附录 A：首期演示脚本建议

1. 新用户在登录页切换到「注册」，使用用户名＋密码注册并自动登录；在个人中心绑定邮箱并确认展示。
2. 进入学习路线，浏览各阶段课程；点击课程在新标签页打开 B 站视频，返回后浏览阶段图文，点击外链题跳转，最后标记完成；确认进度百分比只随阶段完成变化。
3. 做一道客观题，查看判分；再故意答错，查看错题本。
4. 做一道简答题，提交文本答案，查看「判分中」状态、0–100 分与评语；提交低于 60 分的答案，确认进入错题本且榜单不变。
5. 做一道 OJ 题，提交 C++/Python 代码，查看判题结果。
6. 绑定预置 CF 账号，由超级管理员刷新 CF 模拟数据，查看周榜站内 + CF 数据；切换「总榜」查看历史累计。
7. 手动申报牛客本周过题数，确认榜单暂不计分并显示“未审核”；由超级管理员审核通过，查看周榜更新并确认总榜手动累计同步增加；拒绝或改判后确认榜单实时移除/恢复；重复申报同一周数据，确认覆盖不累加并重置审核状态。
8. 两个账号创建/加入对战房间，完成一局对战，查看对战记录；确认对战 AC 同步计入榜单，非 AC 进入错题本。
9. 在个人中心配置 LLM 凭证（演示 Key），确认保存后仅展示脱敏信息；分别提交随机生成、LLM 构造与 LLM 直接生成数据任务，查看对应状态流转并下载文件；确认 LLM 构造模式不展示生成器代码，直接生成模式不产生生成器；删除凭证后确认两种 LLM 模式不可提交并展示配置引导。
10. 切换超级管理员，维护路线/阶段课程/题目（含简答题），审核手动申报，新增运营账号并重置密码；切换到运营账号，确认可维护内容、查看榜单与申报记录，但不能审核申报、不能刷新 CF、不能启用/禁用用户、看不到管理员账号管理。
11. 点击 XCPC 入口，进入站内说明页，再点击页内外链按钮打开外部站点。

## 附录 B：术语表

| 术语 | 说明 |
|---|---|
| 专题 | 知识方向，也是学习路线 |
| 阶段 | 学习路线中的一个学习单元 |
| 课程 | 挂在阶段下的 B 站视频资源，只提供观看入口，不计学习进度 |
| 外链题 | 指向 Codeforces、牛客等外部平台的题目 |
| 站内题 | 平台自建或授权的 OJ 编程题 |
| 客观题 | 判断、单选、多选题 |
| 简答题 | 选手以文本作答的主观题，由 AI 按参考答案与评分要点评分 |
| AI 判分 | 简答题提交后由 LLM 返回 0–100 分与评语；低于 60 分为未通过 |
| 过题 | OJ 编程题首次 AC，包含普通刷题与对战提交 |
| 周榜 | 按北京时间自然周统计的全站过题排名，每周重置 |
| 总榜 | 全部历史累计的全站过题排名，不设重置 |
| 造数据 | 根据题面和数据范围生成测试输入/输出 |
| 随机生成 | 在数据范围内随机产出输入；首期默认造数据模式 |
| LLM 构造 | 由 LLM 生成数据构造器（generator），平台运行构造器产出输入；不展示生成器代码 |
| LLM 直接生成数据 | 由 LLM 直接产出测试输入文件，不生成构造器或 std；平台校验后运行用户 std 产出输出 |
| LLM 凭证 | 选手在个人中心配置的服务商 + API Key + 可选模型；仅用于 LLM 造数据，服务端加密保存并脱敏展示 |
| 预置服务商 | 平台后台维护的可用 LLM 服务商列表；选手只能从中选择，不能自定义 Base URL |
| generator | 数据构造器，按规则生成测试输入；由平台在隔离环境中执行 |
| std | 标准程序，由用户提供，用于生成每组输入对应的输出 |
| AC | Accepted，答案正确 |
