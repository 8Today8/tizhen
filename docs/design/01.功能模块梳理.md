## 1. 项目功能全景

### 1.1 产品主线

题阵面向 ACM/ICPC/CCPC 选手，首期跑通“学—练—战—榜”的训练闭环：

```
学习路线（路线 → 阶段 → 课程）
        │
        ▼
站内题库（OJ 编程题 / 客观题 / 简答题 / 外链题）──► 判题、AI 判分与首次 AC
        │                                   │
        ▼                                   ▼
   学习记录 / 错题本                  周榜 / 历史总榜
        ▲                                   ▲
        │                                   │
   1v1 对战（同题竞速）               CF 同步 / 其他平台手动申报

旁路能力：AI 造数据（出题提效）
支撑能力：账号与权限、运营后台、操作日志
```

首期是**本地演示原型**，重点验证交互与页面结构，不做公网合规、生产级高可用和真实外部平台对接。

### 1.2 角色与端

| 角色 | 端 | 首期职责 |

## 2. 功能模块划分

### 2.1 划分原则

1. **按业务能力与数据归属划分，不按页面划分。** 一个页面可以组合多个模块的数据和操作，例如首页、个人中心、学习记录页。
2. **后台不作为独立业务域。** 路线/阶段/课程管理归学习内容模块，题库管理归题库模块，用户管理归账号模块，榜单管理归榜单模块；后台壳、鉴权、菜单与操作日志单独作为支撑模块。
3. **榜单是派生视图，不拥有原始成绩数据。** 榜单只读取站内提交、外部账号和手动申报，不单独保存排名快照。
4. **同一业务事实只有一个写入方。** “首次 AC”由题库与判题模块判定，榜单只消费该事实；外部成绩由外部成绩接入模块写入。
5. **不新增 PRD 未定义的功能。** 模块职责只覆盖第 3 节范围清单与第 5 节功能需求。

#### M02 外部成绩接入

| 项 | 说明 |
|---|---|
| 职责 | 管理选手的外部平台账号与过题数据：CF 绑定/解绑/模拟校验、周数据与历史累计同步；其他平台按周手动申报及后台审核；统一提供数据来源、审核状态、更新时间 |
| 包含功能 | U-05 CF 绑定、U-06 CF 解绑、U-07 其他平台申报；L-04 申报入口、L-05 CF 同步；A-08 中的刷新 CF、申报记录查看与审核 |
| 不负责 | 榜单排名与展示（M05）；站内 OJ 过题（M04） |
| 核心数据 | ExternalAccount（含 weekly_count、all_time_count、last_sync_at、source）、ManualDeclaration |
| 依赖 | M01（当前选手身份） |
| 被依赖 | M05 榜单 |
| 主要页面 | 个人中心（外部账号区）、榜单页手动申报弹窗、后台榜单管理（刷新、申报记录与审核） |
| 边界 | 一个外部账号只能绑定一个平台用户；解绑后历史数据保留但不再更新；其他平台申报由超级管理员审核，仅审核通过计分；手动申报仅按周提交，总榜不提供申报入口 |

**申报口径**

- 手动申报按“用户 + 平台 + 自然周”存储，同一组合只保留一条；重复提交覆盖原值并重置为未审核。仅审核通过记录计分：周榜取本周通过记录，总榜取全部通过记录之和。
- 超级管理员可通过或拒绝申报并改判，内容运营只读；审核备注选填（≤ 200 字），仅后台可见。
- 跨平台不去重；跨周重复申报可能导致总榜重复累计，PRD 已列为风险。
- 【已确认】同一用户＋同一平台＋同一自然周唯一，重复提交覆盖，不累加。

- 【已确认】路线进度 = 已完成阶段数 / 阶段总数；外链题完成状态只在阶段内单独展示，不计入百分比。
- 课程观看同样不计入进度；学习进度只由阶段完成状态决定。

| 核心数据 | Problem（简答题含参考答案、评分要点、满分固定 100）、ProblemTag、TestData、ObjectiveOption、Submission（含简答文本答案、AI 分数、评语、判分状态） |

| 边界 | 只有 OJ 编程题首次 AC 计入榜单；客观题、简答题、外链题、重复 AC 不计入；题目可被多个阶段引用；已被引用的题目不物理删除，只上下架；SPJ / 交互题后置 |

**首次 AC 判定**

- 首次 AC 是**历史首次**：同一用户对同一 OJ 题只在第一次 AC 时产生一次“过题”事实。
- 周榜取“本周发生的首次 AC”，总榜取“全部历史首次 AC 数”；两者共享同一判定结果，不做两套计数。
- 当前原型通过提交记录判断是否已有 AC，并同时递增周榜/总榜计数；正式设计应改为由提交事实派生。
- 【已确认】对战中的 AC 计入站内首次 AC，周榜/总榜与普通提交使用同一口径；对战中的非 AC 提交进入错题本。
- 【已确认】题目后续下架不回溯已产生的首次 AC，历史 AC 仍计入榜单。

**简答题 AI 判分口径**

- 【已确认】题库新增简答题；后台必须配置参考答案与评分要点，满分固定 100。
- 【已确认】选手提交文本答案后由 AI 返回 0–100 分与评语；低于 60 分视为未通过，并进入错题本。
- 简答题不计入榜单；再次通过不自动移出错题本，仍由选手手动移除。
- AI 判分失败时展示失败原因，允许重新提交，不自动重试。
- AI 评分结果与评语按不可信内容处理，评语展示需转义；评分提示词与密钥仅服务端保存。

## 4. 核心业务流程

### F1 选手注册与登录

- **触发**：未登录访问任意 C 端页面，或主动进入登录页。
- **主流程**：
  1. 登录页切换「登录 / 注册」页签（M01）。
  2. 注册：填写用户名、昵称、密码、确认密码 → 校验格式、唯一性、两次密码一致 → 创建 User → 自动登录 → 首页。
  3. 登录：用户名（大小写不敏感）＋密码 → 校验账号状态 → 建立登录态 → 首页。
  4. 首页加载时组合 M03 学习进度、M05 榜单摘要、M06 错题数。
- **异常/边界**：重复用户名、用户名格式非法、密码少于 6 位、两次密码不一致、密码错误、账号被禁用，均拦截并提示；后台账号不开放注册。
- **涉及模块**：M01；展示聚合层。

### F2 CF 绑定与榜单数据更新

- **触发**：选手在个人中心或榜单页发起 CF 绑定。
- **主流程**：
  1. 输入 CF handle（M02）。
  2. 平台做轻量校验（原型为预置白名单模拟校验），检查该 handle 是否已被其他用户绑定。
  3. 绑定成功，写入 ExternalAccount：本周过题数、历史累计过题数、校验状态、最后同步时间。
  4. M05 周榜读取本周 CF 数，总榜读取历史累计数；页面展示“已校验/模拟数据”和更新时间。
  5. 原型支持后台手动刷新模拟数据；正式环境由 worker 每小时同步，超级管理员可在后台手动触发同步，选手端不提供刷新入口。
- **异常/边界**：非法 handle、重复绑定失败；解绑后历史数据保留但不再更新；一个 CF handle 只能绑定一个平台用户。
- **涉及模块**：M01（身份）、M02、M05。

### F3 其他平台手动申报

- **触发**：选手在榜单页（仅周榜）点击“手动申报”。
- **主流程**：
  1. 填写平台、账号/主页、本周过题数（M02）。
  2. 按“用户 + 平台 + 当前自然周”保存记录，状态为“未审核”，榜单暂不计分。
  3. 超级管理员在后台榜单管理中通过或拒绝；仅通过记录计入周榜/总榜，可改判。
  4. 周榜手动过题数取本周审核通过记录；总榜手动累计取全部审核通过周记录之和。
  5. 榜单页与首页摘要在审核通过/改判后同步更新。
- **异常/边界**：跨周需重新申报；同一用户＋同一平台＋同一自然周只保留一条记录，重复提交覆盖原值并重置审核状态；总榜不提供申报入口；内容运营不可审核；跨周重复申报可能造成总榜重复累计（PRD 已列风险）。
- **涉及模块**：M02、M05。

### F4 学习路线浏览与阶段完成

- **触发**：选手进入学习路线。
- **主流程**：
  1. 路线列表展示路线、简介、阶段数、完成进度（M03）。
  2. 路线详情展示阶段顺序、完成状态、每阶段课程列表（M03）。
  3. 阶段详情展示图文内容、视频课程、外链题、站内练习题；点击课程在新标签页打开 B 站（M03）；点击题目跳转外链或做题页（M03 → M04）。
  4. 选手手动标记阶段完成/取消，记录完成时间（M03）。
  5. 外链题：由选手手动标记完成/取消；本版不提供 CF 单题自动识别（当前无单题 AC 数据源）。
- **异常/边界**：不强制解锁；课程观看不计进度；外链题完成不计榜单；进度百分比只按阶段完成数计算，外链题完成单独展示。
- **涉及模块**：M03、M04。

### F5 站内 OJ 刷题与首次 AC

- **触发**：选手从题库、阶段或首页随机题进入 OJ 题目。
- **主流程**：
  1. 题库列表按专题、难度、题型、来源筛选，按标题搜索（M04）。
  2. 题目详情展示题面、输入输出格式、样例、限制（M04）。
  3. 选手选择 C++/Python，编写代码并提交（M04）。
  4. 判题返回 AC/WA/TLE/MLE/RE/CE，保存 Submission（M04）。
  5. 若为 AC 且是历史首次：产生“首次 AC”事实，周榜本周计数 +1、总榜历史计数 +1（M04 → M05）。
  6. 若为非 AC：写入错题本，按题目聚合，更新最近错误与次数（M04 → M06）。
- **异常/边界**：重复 AC 不重复计入；客观题和简答题不进入该流程；对战中的 AC 同样计入站内首次 AC，非 AC 同样进入错题本。
- **涉及模块**：M04、M05、M06。

### F6 客观题/简答题作答与错题收集

- **触发**：选手打开客观题或简答题。
- **主流程**：
  1. 客观题展示题干与选项（判断/单选/多选）；简答题展示题干与文本输入框（M04）。
  2. 客观题提交后立即自动判分，展示正确/错误与正确答案，解析字段可选（M04）。
  3. 简答题提交后进入 AI 判分，展示「判分中」；完成后展示 0–100 分与评语（M04 → 外部 LLM）。
  4. 客观题错误答案、简答题低于 60 分的未通过记录写入错题本（M04 → M06）。
  5. 保存作答记录与判分结果，供学习记录页查询（M04 → M06）。
- **异常/边界**：客观题、简答题均不计入榜单；错题本同一题只保留一条聚合记录；再次答对/简答再次通过不自动移除；AI 判分失败展示原因并允许重新提交，不自动重试。
- **涉及模块**：M04、M06、外部 LLM 判分服务。

### F7 榜单查看与切换

- **触发**：选手进入榜单页或操作首页榜单摘要。
- **主流程**：
  1. 默认展示周榜；顶部页签切换周榜/总榜（M05）。
  2. M05 聚合 M04 站内首次 AC、M02 CF 数据与审核通过的手动申报，计算总分与排名。
  3. 展示前 20 名、我的排名、数据来源标签、校验/审核状态、更新时间；可查看更多（M05）。
  4. 首页摘要卡使用同一组页签与前 5 名数据，“查看完整榜单”进入对应页签（展示聚合层 + M05）。
  5. 周榜提供手动申报入口；申报由超管在后台审核，CF 刷新仅超管在后台执行；总榜只读（M02 / M05）。
- **异常/边界**：总分相同按站内过题数降序，仍相同并列；总榜不提供申报；未审核/已拒绝申报不计分；被禁用用户移出榜单但保留数据；默认展示前 20 名，查看更多按分页加载。
- **涉及模块**：M05、M02、M04、M01。

### F8 1v1 对战

- **触发**：选手进入对战大厅创建或加入房间。
- **主流程**：
  1. 创建房间：选择难度/专题筛选条件，生成房间码/邀请链接（M07）。
  2. 另一名选手通过房间码/链接加入，双方准备（M07）。
  3. 房主开始，M04 按筛选条件从全局题库随机抽取一道传统题，双方看到同题（M07 → M04）。
  4. 30 分钟倒计时；双方提交代码，M04 判题；先 AC 者胜（M07 + M04）。
  5. 超时无人 AC 判平局；主动退出或断线判负（M07）。
  6. 结束后生成对战记录，展示对手、题目、双方提交状态、结果、开始/结束时间（M07）。
  7. 对战中的 AC 计入站内首次 AC，同步更新周榜/总榜；非 AC 提交进入错题本。
- **异常/边界**：不做随机匹配、积分/段位、观战、回放；双方代码互不可见；断线立即判负、不重连。
- **涉及模块**：M07、M04、M01、M05、M06。

### F9 AI 造数据

- **触发**：选手进入造数据工作台。
- **主流程**：
  1. 进入个人中心配置 LLM 凭证：选择预置服务商、填写 API Key 与可选模型；保存时由服务端校验可用性，失败则拒绝保存；凭证加密保存，页面只展示脱敏信息（M01 + M08）。
  2. 选择生成方式：随机生成（默认）/ LLM 构造 / LLM 直接生成数据；切换不丢失已填表单；未配置有效凭证时两种 LLM 模式禁用并展示配置引导（M08 + M01）。
  3. 填写题目名称、题面、输入/输出格式、std、数据范围、组数、时限/内存；LLM 模式可填“特殊构造要求”（M08）。
  4. 提交任务：创建前复检凭证；同一选手已有进行中的 LLM 任务时拒绝提交；异步执行（M08）：
     - 随机模式：按数据范围生成输入 → 运行 std 产出输出；
     - LLM 构造模式：LLM 构造中 → 生成器就绪 → 运行构造器生成输入 → 运行 std 产出输出；
     - LLM 直接生成模式：LLM 生成数据中 → 逐组校验格式/范围 → 运行 std 产出输出。
  5. 状态流转：待生成 / LLM 构造中 / LLM 生成数据中 / 生成中 / 成功 / 失败（M08）。
  6. 成功：展示每组文件大小、std 用时、校验信息，支持单组或打包下载（M08）。
  7. 失败：终止并展示失败阶段与原因，不自动重试；选手更新凭证后可手动重新提交（M08）。
  8. 任务列表与详情可查询；生成器代码仅在 LLM 构造模式产生且不展示；文件保留 7 天（M08）。
- **异常/边界**：凭证未配置/无效、凭证在执行中失效或欠费、LLM 失败/超时、生成器无法执行、LLM 直接生成的数据不符合格式/范围、std 运行失败均终止；任务进行中禁止替换/删除凭证；生成器与 std 必须隔离执行；LLM 输出视为不可信输入。
- **涉及模块**：M08、M01；外部 LLM/沙箱/文件存储。

### F10 运营后台内容维护与审计

- **触发**：管理员登录后台。
- **主流程**：
  1. 管理员用户名＋密码登录（M09 + M01）。
  2. 按角色展示菜单：超管全部；内容运营无角色管理、无用户启禁用、无管理员账号管理、无手动申报审核、无 CF 刷新（M09 + M01 权限）。
  3. 路线/阶段/课程增删改查、排序、发布（M03）；保存后 C 端路线详情/阶段详情立即生效。
  4. OJ/客观/简答/外链题增删改查、上下架（M04）；简答题须配置参考答案与评分要点后方可上架；被引用题目不可物理删除。
  5. 用户列表、搜索、详情、启用/禁用（M01，仅超管可启禁用）；详情展示 LLM 凭证配置状态、服务商与最近校验结果，不展示 Key。
  6. 超级管理员在角色管理页维护管理员账号：新增运营账号、启用/禁用、重置密码（M01）。
  7. 榜单管理查看周榜/总榜、手动申报记录；超级管理员可审核通过/拒绝申报并填写选填备注，内容运营只读；刷新 CF 模拟数据仅超管可操作（M05 + M02）。
  8. 造数据任务列表与详情查看（M08）。
  9. 所有关键操作写入操作日志，可在后台查询（M09）。
- **异常/边界**：内容保存后直接生效，无内容审核流；非法 B 站链接阻止保存；操作日志仅管理员可访问；手动申报审核与刷新 CF 模拟数据仅超级管理员可操作。
- **涉及模块**：M09、M01、M03、M04、M05、M08。

## 8. 阶段结论

### 8.1 本阶段结论

1. 首期功能可归纳为 **9 个业务/支撑模块**：账号与权限、外部成绩接入、学习内容与进度、题库与判题、榜单、学习记录与错题本、对战、AI 造数据、运营后台支撑与审计。
2. 核心闭环为：**学习路线 → 站内刷题 → 首次 AC → 周榜/总榜**，外部成绩（CF、手动申报）补充榜单；对战和造数据是旁路能力。
3. 榜单是**派生视图**，不拥有原始成绩数据；站内首次 AC 的唯一判定方是题库与判题模块。
4. 后台不是独立业务域：各业务模块提供管理能力，后台支撑模块负责登录、菜单、权限落地和操作日志。
5. 课程、外链题完成、简答题、错题本均**不参与榜单统计**。
6. 当前原型与 PRD 的 10 处不一致已全部闭合：8 处通过功能模块梳理确认，外链题完成实体与对战记录模型 2 处已在数据库设计阶段确认（见 7.3 与 `03.数据库设计.md`）。
7. 本轮确认的关键口径：对战提交全部计入榜单与错题本；禁用用户移出榜单但保留数据；手动申报按周覆盖；CF 刷新仅超管；榜单分页；下架题目历史 AC 仍计入；管理员账号管理首期实现；邮箱绑定按 P0 实现基础绑定。
8. v0.7 新增两项能力：简答题 AI 判分（0–100 分＋评语，低于 60 分进错题本，不计榜）；AI 造数据新增「LLM 直接生成数据」第三模式（只生成输入，std 由用户提供，逐组校验）。
9. PRD 已由 v0.5 升级至 v0.6，再升级至 v0.7，再升级至 v0.8，再升级至 v0.9；受影响章节与验收、决策记录已同步（见 7.4）。
10. v0.8 新增选手自带 LLM 凭证：仅用于两种 LLM 造数据模式，简答判分仍用平台密钥；单人单份、加密保存、保存与执行前双校验、失败不自动重试、每人最多 1 个进行中 LLM 任务。
11. v0.9 新增手动申报审核：超级管理员可通过/拒绝并改判，内容运营只读；仅审核通过计入周榜/总榜；审核备注选填且仅后台可见。
