## 1. 设计范围与原则

### 1.1 覆盖范围

本文覆盖首期 9 个模块与展示聚合层所需的 109 个 HTTP 接口和 1 个 WebSocket 入口：

| 模块 | 本文对应章节 |
|---|---|
| M01 账号与权限 | 6.1、6.9 中的管理员账号部分 |
| M02 外部成绩接入 | 6.2 |
| M03 学习内容与进度 | 6.3 |
| M04 题库与判题 | 6.4 |
| M05 榜单 | 6.5 |
| M06 学习记录与错题本 | 6.6 |
| M07 对战 | 6.7 |
| M08 AI 造数据 | 6.8 |
| M09 后台支撑与审计 | 6.9 |
| 展示聚合层（首页、导航、XCPC、个人中心） | 6.10、6.11 |

### 1.2 基本原则

1. 默认 REST 风格；资源用名词，HTTP 方法表达语义。
2. 选手端统一前缀 `/api/v1`，运营后台统一前缀 `/api/v1/admin`。
3. 所有业务接口必须登录后访问；仅注册、登录、CSRF 初始化等少量接口公开。
4. 后端必须校验全部输入，前端校验只做体验优化。
5. 响应字段以 `03.数据库设计.md` 的字段为唯一来源；不得返回数据库不存在或未经确认的业务字段。
6. 内部字段、敏感字段永不返回：`password_hash`、`api_key_ciphertext`、`generator_code`、测试数据内容、客观题正确答案（提交前）、简答题参考答案（提交前）。
7. 写操作必须同时校验「登录态 + 角色 + 资源归属 + 当前状态」，前端隐藏按钮不作为权限边界。
8. 异步接口不假装同步完成：判题、简答题 AI 判分、造数据任务、CF 刷新均返回明确状态，由前端轮询或等待事件。
9. 所有后台写操作由 AOP 审计，审计失败业务回滚；API 不提供修改或删除操作日志的入口。

## 2. 全局契约约定

### 2.1 路径与方法

| 项 | 约定 |
|---|---|
| 协议 | 开发/内网可用 HTTP；公网必须 HTTPS/WSS |
| 基础路径 | 选手端 `/api/v1`；运营后台 `/api/v1/admin` |
| 版本 | 路径版本 `v1`；破坏性变更升级版本，不在原路径上静默改字段 |
| 命名风格 | 路径小写短横线或单词；JSON 字段 `camelCase`；枚举值沿用数据库 `snake_case` |
| 路径参数 | 用于资源标识，例如 `/problems/{problemId}`、`/battles/rooms/{roomId}` |
| 查询参数 | 用于筛选、排序、分页；不承载密码、令牌、API Key |
| 请求体 | `application/json; charset=utf-8`；文件下载除外 |
| 响应体 | JSON 统一包络；文件下载返回二进制流 |
| HTTP 方法 | `GET` 读取、`POST` 创建/执行、`PUT` 全量替换/幂等设置、`PATCH` 局部更新、`DELETE` 删除/解除 |

### 2.2 请求与响应格式

**统一成功响应：**

```json
{
  "success": true,
  "code": "OK",
  "message": "ok",
  "data": {},
  "requestId": "3f3c0f5f7d2a4e0f",
  "timestamp": "2026-11-09T10:20:30.123Z"
}
```

**统一失败响应：**

```json
{
  "success": false,
  "code": "AUTH_INVALID_CREDENTIALS",
  "message": "用户名或密码错误",
  "data": null,
  "fieldErrors": [
    { "field": "username", "message": "用户名不能为空" }
  ],
  "requestId": "3f3c0f5f7d2a4e0f",
  "timestamp": "2026-11-09T10:20:30.123Z"
}
```

约定：

- `success` 与 HTTP 状态码必须一致：`2xx` 为 `true`，`4xx/5xx` 为 `false`；不得用 HTTP 200 包装业务失败。
- `code` 为稳定字符串错误码，客户端只依赖 `code` 做分支，不依赖 `message` 文案。
- `fieldErrors` 仅在参数校验失败时出现；字段名为 API 字段名。
- `requestId` 每次请求唯一，错误排查时提供给用户；日志中必须可检索。
- `timestamp` 为服务端 UTC 时间。
- `204 No Content` 响应无响应体。
- 文件下载成功时返回二进制流，不套 JSON；下载失败仍返回上述 JSON 包络。

### 2.3 ID、时间与枚举

| 项 | 约定 |
|---|---|
| ID | 数据库 `BIGINT UNSIGNED` 在 JSON 中统一序列化为**十进制字符串**，避免 JavaScript 精度丢失；路径参数同样接受字符串 |
| 时间 | `DATETIME(3)` 统一输出 ISO 8601 UTC，例如 `2026-11-09T10:20:30.123Z`；输入如无时区按 UTC 解释 |
| 日期 | `DATE` 输出 `YYYY-MM-DD`；自然周字段必须是周一日期 |
| 金额 | 本期无金额 |
| 分数 | JSON number，保留两位小数；`DECIMAL(5,2)` |
| 布尔 | JSON `true/false`；数据库 `TINYINT` 0/1 由后端转换 |
| 枚举 | 取值与 `03.数据库设计.md` 第 5 节一致；未知枚举值一律拒绝，不做“容错猜测” |
| 空值 | 可选字段无值时返回 `null`；不返回空字符串冒充缺失 |

> 本版采用 `camelCase` JSON 字段名与字符串 ID（已确认，见 9.2 Q-API-05），是接口层命名约定，不改变数据库字段。字段与数据库列的对应关系见第 7 节。

### 2.4 分页、排序与筛选

| 参数 | 类型 | 默认 | 约束 | 说明 |
|---|---|---|---|---|
| `page` | integer | 1 | ≥ 1 | 页码从 1 开始 |
| `pageSize` | integer | 20 | 1–100 | 榜单默认 20；后台列表默认 20 |
| `keyword` | string | — | ≤ 100 字符 | 模糊搜索，具体字段由接口说明 |
| `sort` | string | 接口固定 | 仅允许接口列出的枚举 | 不接受任意 SQL 排序字段 |

分页响应结构：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0,
  "totalPages": 0
}
```

约定：

- 页码越界返回空 `items`，不报错。
- `totalPages = ceil(total / pageSize)`；`total = 0` 时为 0。
- 榜单、错题本等需要“我的排名/我的统计”的接口，可在分页结构同级附加 `me` 等字段，见各接口定义。
- 后台列表默认按 `createdAt DESC`；内容管理列表可按 `sortOrder ASC, id ASC`，以接口说明为准。

### 2.5 参数校验通用规则

| 类型 | 规则 |
|---|---|
| 用户名 | `^[A-Za-z0-9_]{3,20}$`，大小写不敏感唯一 |
| 密码 | 6–64 字符；不得包含首尾空格；服务端 BCrypt 哈希 |
| 昵称 | 1–64 字符，去除首尾空格后非空 |
| 邮箱 | 合法邮箱格式，≤ 254 字符；首期不做验证码验证 |
| 手机号 | 可选，6–32 字符；仅本人与后台可见 |
| URL | 只接受 `http://` 或 `https://`，≤ 512 字符；课程必须是 B 站视频链接 |
| 代码 | OJ 代码 ≤ 64 KB；std 代码 ≤ 64 KB |
| 文本答案 | 1–10,000 字符，去除首尾空格后非空 |
| 题面/说明 | ≤ 100,000 字符 |
| 标签 | 单个 ≤ 64 字符；每题 ≤ 20 个 |
| 数组 | 未特别说明时 ≤ 100 项；空数组是否允许由接口说明 |
| 枚举 | 必须属于接口列出的有限集合 |
| 日期 | `YYYY-MM-DD`；周起始日期必须为周一 |

校验失败统一返回 `400 COMMON_VALIDATION_FAILED`，并给出 `fieldErrors`；不得把数据库异常、堆栈或 SQL 返回给客户端。

### 2.6 异步接口约定

| 场景 | 创建响应 | 后续查询 |
|---|---|---|
| OJ 提交判题 | `201 Created`，`data.status=pending` 或 `judging` | `GET /api/v1/submissions/{id}` 轮询 |
| 简答题 AI 判分 | `201 Created`，`data.status=grading` | 同上；判分失败为 `status=failed` |
| 客观题判分 | `201 Created`，`data.status=finished` | 无需轮询 |
| 造数据任务 | `202 Accepted`，`data.status=pending` | `GET /api/v1/datagen/tasks/{id}` 轮询 |
| CF 刷新 | `202 Accepted` | 后台榜单/账户列表查看 `lastSyncAt` |

轮询建议：前端 500ms 起，逐步退避到 2s；不得无限高频轮询。服务端不因轮询创建重复业务记录。

### 2.7 文件下载约定

- 造数据文件下载路径必须同时校验登录态与任务归属；管理员可下载任意任务文件。
- 文件名使用随机化存储名，`Content-Disposition` 中给出安全文件名；禁止路径穿越。
- 文件过期返回 `410 DATAGEN_FILE_EXPIRED`，不返回服务器真实路径。
- 打包下载返回 ZIP；打包内容只包含仍保留的输入/输出文件。
- 不提供生成器代码下载接口；任何响应不得包含 `generatorCode`。

## 3. 认证、会话与权限

### 3.1 双会话体系

| 端 | 会话 Cookie | CSRF Cookie | 登录入口 |
|---|---|---|---|
| 选手端 | `TIZHEN_SID`（HttpOnly、SameSite=Lax） | `XSRF-TOKEN`（非 HttpOnly，供前端读取） | `/api/v1/auth/*` |
| 运营后台 | `TIZHEN_ADMIN_SID`（HttpOnly、SameSite=Lax） | `ADMIN-XSRF-TOKEN`（非 HttpOnly） | `/api/v1/admin/auth/*` |

- 选手与管理员是两套账号表、两套会话；同一浏览器可同时登录，互不覆盖。
- 管理员会话不能调用选手端接口；选手会话也不能调用后台接口。
- 会话默认超时：选手端空闲 2 小时、绝对 12 小时；后台空闲 30 分钟、绝对 8 小时。超时返回 `401 AUTH_SESSION_EXPIRED`。
- 禁用账号时删除该账号全部会话；下一次请求必须重新登录。
- Cookie 在 HTTPS 下加 `Secure`；开发环境可关闭 `Secure`，但不得关闭 `HttpOnly`（CSRF Cookie 除外）。

### 3.2 CSRF

1. 前端首次进入登录页调用 `GET /api/v1/auth/csrf` 或 `GET /api/v1/admin/auth/csrf`，服务端设置对应 CSRF Cookie 并返回 token。
2. 所有 `POST / PUT / PATCH / DELETE` 请求必须带请求头 `X-XSRF-TOKEN`，值来自对应 CSRF Cookie；登录、注册、退出也不例外。
3. 登录成功后轮换会话与 CSRF Token；响应返回新的 `csrfToken`，前端立即替换。
4. CSRF 校验失败返回 `403 COMMON_CSRF_INVALID`；前端重新获取 token 后可重试一次。
5. GET 请求不得产生业务副作用。

### 3.3 登录与限流

- 选手登录：用户名大小写不敏感；错误统一提示“用户名或密码错误”，不区分账号不存在与密码错误。
- 管理员登录：同规则；不开放注册。
- 登录失败限流：同一用户名 + IP 在 15 分钟内连续失败 5 次，返回 `429 COMMON_RATE_LIMITED`，锁定时长 15 分钟。
- 账号禁用：登录返回 `403 AUTH_ACCOUNT_DISABLED`；已登录会话立即失效。
- 密码只以 BCrypt 哈希保存，任何接口、日志、异常不得出现明文。

### 3.4 角色与权限矩阵

首期只有两个管理员角色，角色编码与数据库 `admin_role.code` 一致：

| 能力 | `super_admin` | `content_operator` |
|---|---|---|
| 后台登录 | ✓ | ✓ |
| 路线/阶段/课程维护 | ✓ | ✓ |
| 四类题目维护、测试数据、上下架 | ✓ | ✓ |
| 用户列表/详情查看 | ✓ | ✓ |
| 用户新增、启停用、批量删除、重置密码、更换头像 | ✓ | ✗ |
| 头像文件上传（仅落盘，不绑定用户） | ✓ | ✓ |
| 管理员账号新增/启禁用/重置密码 | ✓ | ✗ |
| 角色查看 | ✓ | ✗ |
| 榜单查看、手动申报记录查看 | ✓ | ✓ |
| 手动申报审核（通过/拒绝） | ✓ | ✗ |
| 刷新 CF 数据 | ✓ | ✗ |
| 造数据任务查看/文件下载 | ✓ | ✓ |
| 操作日志查看 | ✓ | ✓ |

接口级权限标记约定：

- `公开`：无需登录。
- `选手`：需要有效选手会话。
- `运营`：`super_admin` 或 `content_operator` 均可。
- `超管`：仅 `super_admin`。
- `本人`：需要选手会话，且只能操作 `userId = 当前用户` 的资源。

### 3.5 资源归属与越权规则

1. 选手只能读取自己的提交、错题本、造数据任务、外部账号、手动申报、对战记录。
2. 对战房间只对创建者和对手可见；非参与者不得读取房间详情或题目。
3. 管理员不能读取选手 LLM Key 明文或末四位；用户详情只返回配置状态、服务商、模型与最近校验结果。
4. 造数据任务详情不返回 `generatorCode`；管理员也不例外。
5. 题目测试数据、客观题正确答案、简答题参考答案与评分要点只对后台管理员开放；选手只能在提交结果中看到客观题答案/简答题参考答案。
6. 任何按 ID 读取资源的接口都必须做归属校验，不能只靠前端不展示。

## 4. 统一错误码

### 4.1 HTTP 状态码使用

| HTTP | 语义 | 示例 |
|---|---|---|
| 200 | 查询或更新成功 | 获取列表、更新资料 |
| 201 | 资源创建成功 | 注册、提交、创建房间 |
| 202 | 已接受异步任务 | 创建造数据任务、CF 刷新 |
| 204 | 成功且无响应体 | 退出、解绑、软删除、取消房间 |
| 400 | 参数格式/字段校验失败 | 用户名格式、缺少必填字段 |
| 401 | 未登录或会话过期 | 无会话、会话超时 |
| 403 | 已登录但无权限/CSRF 失败/账号禁用 | 内容运营禁用用户 |
| 404 | 资源不存在或对当前用户不可见 | 他人任务、已删除内容 |
| 409 | 当前状态冲突/唯一性冲突 | 房间已开始、用户名重复、有引用不能删除 |
| 410 | 资源曾存在但已过期 | 造数据文件已清理 |
| 413 | 请求体过大 | 代码/测试数据超限 |
| 415 | 不支持的媒体类型 | 非 JSON 请求体 |
| 429 | 触发限流 | 登录失败过多 |
| 500 | 未预期服务端错误 | 内部异常 |
| 503 | 依赖不可用 | 判题队列/数据库暂不可用 |

### 4.2 业务错误码清单

| 错误码 | HTTP | 含义 | 典型场景 |
|---|---|---|---|
| `OK` | 200/201/202/204 | 成功 | — |
| `COMMON_VALIDATION_FAILED` | 400 | 字段校验失败 | 缺字段、长度/格式非法 |
| `COMMON_INVALID_PARAM` | 400 | 查询参数非法 | 枚举、日期、分页非法 |
| `COMMON_UNAUTHENTICATED` | 401 | 未登录 | 无会话 |
| `COMMON_CSRF_INVALID` | 403 | CSRF 校验失败 | 缺少/错误 token |
| `COMMON_FORBIDDEN` | 403 | 无权限 | 内容运营访问超管接口 |
| `COMMON_NOT_FOUND` | 404 | 资源不存在 | 通用资源 |
| `COMMON_CONFLICT` | 409 | 通用状态冲突 | 状态不允许当前操作 |
| `COMMON_RATE_LIMITED` | 429 | 限流 | 登录失败过多 |
| `COMMON_PAYLOAD_TOO_LARGE` | 413 | 请求体过大 | 代码/测试数据超限、头像超过 2MB |
| `COMMON_UNSUPPORTED_MEDIA_TYPE` | 415 | 媒体类型不支持 | 非 JSON、头像不是 JPG/PNG |
| `COMMON_INTERNAL_ERROR` | 500 | 服务端错误 | 未捕获异常 |
| `AUTH_INVALID_CREDENTIALS` | 401 | 用户名或密码错误 | 登录失败 |
| `AUTH_ACCOUNT_DISABLED` | 403 | 账号已禁用 | 登录/会话校验 |
| `AUTH_SESSION_EXPIRED` | 401 | 会话过期 | 空闲超时 |
| `AUTH_USERNAME_TAKEN` | 409 | 用户名已存在 | 注册 |
| `AUTH_EMAIL_TAKEN` | 409 | 邮箱已被绑定 | 注册/资料修改 |
| `AUTH_ADMIN_USERNAME_TAKEN` | 409 | 管理员用户名已存在 | 新增管理员 |
| `AUTH_LAST_SUPER_ADMIN` | 409 | 不能禁用唯一超级管理员 | 管理员启禁用 |
| `AUTH_SELF_DISABLE` | 409 | 不能禁用自己 | 管理员启禁用 |
| `LLM_PROVIDER_UNSUPPORTED` | 400 | 服务商不在预置列表 | 保存凭证 |
| `LLM_CREDENTIAL_INVALID` | 400 | Key 校验失败 | 保存凭证 |
| `LLM_CREDENTIAL_NOT_CONFIGURED` | 409 | 未配置有效凭证 | 创建 LLM 造数据任务 |
| `LLM_CREDENTIAL_IN_USE` | 409 | 进行中任务占用凭证 | 替换/删除凭证 |
| `EXTERNAL_PLATFORM_UNSUPPORTED` | 400 | 外部平台不支持 | CF 绑定 |
| `EXTERNAL_HANDLE_INVALID` | 400 | Handle 格式非法 | CF 绑定 |
| `EXTERNAL_HANDLE_TAKEN` | 409 | Handle 已被其他用户绑定 | CF 绑定 |
| `EXTERNAL_ACCOUNT_ALREADY_BOUND` | 409 | 当前用户已绑定该平台账号 | CF 绑定 |
| `EXTERNAL_ACCOUNT_NOT_FOUND` | 404 | 外部账号不存在或已解绑 | 解绑 |
| `MANUAL_DECLARATION_NOT_FOUND` | 404 | 申报记录不存在 | 修改/删除/审核 |
| `MANUAL_DECLARATION_WEEK_LOCKED` | 409 | 非当前周不可修改 | 修改/删除历史申报 |
| `LEARNING_ROUTE_NOT_FOUND` | 404 | 路线不存在/未发布 | 路线详情 |

#### 6.1.1 选手认证与资料

**AUTH-01 `GET /api/v1/auth/csrf`**

响应 `200`：

```json
{
  "token": "5d0f...",
  "headerName": "X-XSRF-TOKEN",
  "cookieName": "XSRF-TOKEN"
}
```

规则：设置 CSRF Cookie；不要求登录；可重复调用，旧 token 失效。

**AUTH-02 `POST /api/v1/auth/register`**

请求体：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `username` | string | 是 | 3–20 位字母/数字/下划线 | 全局唯一，大小写不敏感 |
| `nickname` | string | 是 | 1–64 字符 | 站内展示昵称 |
| `password` | string | 是 | 6–64 字符 | 不返回、不记录 |
| `confirmPassword` | string | 是 | 与 `password` 一致 | 服务端再次校验 |

响应 `201 UserSession`；同时建立选手会话并轮换 CSRF Token。
业务规则：用户名重复返回 `409 AUTH_USERNAME_TAKEN`；不校验邮箱验证码；注册成功后自动登录；管理员账号不能通过此接口创建。

**AUTH-03 `POST /api/v1/auth/login`**

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名，大小写不敏感 |
| `password` | string | 是 | 密码 |

响应 `200 UserSession`。
业务规则：账号不存在与密码错误统一返回 `401 AUTH_INVALID_CREDENTIALS`；禁用账号返回 `403 AUTH_ACCOUNT_DISABLED`；连续失败触发 `429 COMMON_RATE_LIMITED`。

**AUTH-04 `POST /api/v1/auth/logout`**

响应 `204`。删除当前选手会话；无会话时仍返回 `204`（幂等）。

**ME-01 `GET /api/v1/me`**

响应 `200 UserProfile`。

**ME-02 `PATCH /api/v1/me`**

请求体（全部可选，至少传一个）：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `nickname` | string | 1–64 字符 | 昵称 |
| `email` | string | 合法邮箱，≤ 254 | 设置/修改绑定邮箱；不允许清空 |
| `phone` | string | 6–32 字符 | 可选手机号；不允许通过空字符串清空，需传 `null` 显式清空 |
| `avatarUrl` | string \| null | ≤ 512；站内头像路径或 http/https URL | 推荐使用 ME-04 上传后自动绑定；传 `null` 清除头像 |
| `school` | string \| null | ≤ 128 字符 | 学校 |

响应 `200 UserProfile`。
业务规则：`email` 全局唯一，冲突返回 `409 AUTH_EMAIL_TAKEN`；邮箱不做验证码验证；手机号不公开展示；不提供密码修改接口（本期 PRD 未定义）。

**ME-03 `GET /api/v1/me/stats`**

响应 `200`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `learning.completedStages` | integer | 已完成且当前仍发布的阶段数 |
| `learning.totalStages` | integer | 已发布路线下已发布阶段总数 |
| `submissions.total` | integer | 提交/作答总数 |
| `submissions.ojAcCount` | integer | OJ 首次 AC 数 |
| `submissions.objectiveAnswered` | integer | 客观题作答数 |
| `submissions.shortAnswerAnswered` | integer | 简答题作答数 |
| `wrongBook.activeCount` | integer | 未移除错题数 |
| `battles.total` | integer | 对战总数 |
| `battles.wins` | integer | 胜场 |
| `battles.losses` | integer | 负场 |
| `battles.draws` | integer | 平局 |
| `leaderboard.week.rank` | integer \| null | 本周排名；无成绩为 null |
| `leaderboard.week.score` | number | 本周总分 |
| `leaderboard.allTime.rank` | integer \| null | 总榜排名 |
| `leaderboard.allTime.score` | number | 总分 |

规则：只统计当前用户；被禁用账号无法访问；榜单排名与榜单接口使用同一口径；不返回他人数据。

**ME-04 `POST /api/v1/me/avatar`**

请求：`multipart/form-data`，文件字段 `file`。

| 约束 | 说明 |
|---|---|
| 格式 | 仅 JPG / PNG；按文件头魔数识别，不信任扩展名 |
| 大小 | ≤ 2MB |
| 尺寸 | 宽、高均 ≤ 4096px |
| 归属 | 仅当前登录选手本人 |

响应 `200 UserProfile`（`avatarUrl` 为服务器签发的站内相对路径，如 `/api/v1/media/avatar/2026/11/11/{uuid}.png`）。

业务规则：
- 上传成功后立即绑定到当前用户，并删除旧头像文件；绑定失败时清理刚写入的新文件。
- 文件以 UUID 命名，路径不可枚举；前端直接将 `avatarUrl` 用作 `img` 的 `src`。
- 超过大小返回 `413 COMMON_PAYLOAD_TOO_LARGE`；格式不符返回 `415 COMMON_UNSUPPORTED_MEDIA_TYPE`；空文件或尺寸超限返回 `422 COMMON_VALIDATION_FAILED`。

**MEDIA-01 `GET /api/v1/media/avatar/**`**

响应 `200`：头像二进制（`image/jpeg` 或 `image/png`），不套 `ApiResponse` 包络。
规则：公开读取，无需登录；仅接受服务器签发的合法对象键；响应带 `Cache-Control: public, max-age=604800, immutable` 与 `X-Content-Type-Options: nosniff`；非法或不存在路径返回 `404 COMMON_NOT_FOUND`。

#### 6.1.2 LLM 凭证

| 编号 | 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|---|
| CRED-01 | GET | `/api/v1/llm-providers` | 选手 | 获取预置服务商与默认模型 |
| CRED-02 | GET | `/api/v1/me/llm-credential` | 选手 | 查看自己的凭证脱敏信息 |

**CRED-01 `GET /api/v1/llm-providers`**

响应 `200`：

```json
{
  "items": [
    {
      "provider": "deepseek",
      "name": "DeepSeek",
      "defaultModel": "deepseek-chat",
      "models": ["deepseek-chat", "deepseek-reasoner"]
    }
  ]
}
```

规则：只返回预置服务商；不允许客户端提交自定义 Base URL；模型列表为服务端配置，可能随部署变化。

**CRED-02 `GET /api/v1/me/llm-credential`**

响应 `200 LlmCredentialView`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `configured` | boolean | 是否已配置 |
| `provider` | string \| null | 服务商 |
| `providerName` | string \| null | 服务商展示名 |
| `model` | string \| null | 模型；空表示服务端默认 |
| `apiKeyMasked` | string \| null | 仅末四位，例如 `****a1b2` |
| `status` | string \| null | `valid` / `invalid` / `deleted` |
| `lastValidatedAt` | string \| null | 最近校验时间 |
| `lastValidationError` | string \| null | 脱敏后的校验失败原因 |
| `hasActiveTask` | boolean | 是否有进行中的 LLM 任务 |

规则：未配置时返回 `configured=false` 与 null 字段，不返回 404；永不返回明文或密文。

**CRED-03 `PUT /api/v1/me/llm-credential`**

请求体：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `provider` | string | 是 | `deepseek` / `qwen` / `zhipu` / `openai` | 预置服务商 |
| `apiKey` | string | 是 | 8–512 字符 | 仅服务端加密保存，不写日志 |
| `model` | string \| null | 否 | ≤ 64 字符；必须属于服务商允许列表或为空 | 空表示默认模型 |

响应 `200 LlmCredentialView`。
业务规则：

1. 保存前服务端调用服务商轻量校验；失败返回 `400 LLM_CREDENTIAL_INVALID`，不保存。
2. 每位选手仅一份；已有有效凭证时本接口整体替换。
3. 有进行中的 LLM 任务时返回 `409 LLM_CREDENTIAL_IN_USE`，禁止替换。
4. 服务商不支持返回 `400 LLM_PROVIDER_UNSUPPORTED`。
5. API Key 不得出现在日志、异常、响应、审计详情中；失败原因需脱敏。

**CRED-04 `DELETE /api/v1/me/llm-credential`**

响应 `204`。软删除并清空密文与末四位；有进行中的 LLM 任务时返回 `409 LLM_CREDENTIAL_IN_USE`；删除后历史任务保留服务商/模型快照。

#### 6.7.2 WebSocket 对战事件

| 项 | 约定 |
|---|---|
| 路径 | `wss://<host>/ws/battle/rooms/{roomId}` |
| 鉴权 | 握手时校验选手会话 Cookie；仅房间参与者可连接 |
| 数据格式 | JSON 文本帧，字段 `type` + `payload` + `serverTime` |
| 客户端请求 | 只发送心跳 `battle.pong`；所有状态变更走 REST，避免双写 |
| 服务端推送 | 房间快照、加入、连接状态、准备、开始、提交状态、结束、错误 |
| 重连 | 断开后前端可重新连接 `WS-01` 并调用 `BAT-04` 获取最新快照；`ongoing` 中断线按规则判负且不恢复比赛，`waiting` / `ready` 中断线不判负 |

**连接成功后服务端推送：**

```json
{
  "type": "battle.snapshot",
  "payload": { "room": { "id": "10", "roomCode": "ABCD1234", "status": "ongoing" } },
  "serverTime": "2026-11-09T10:20:30.123Z"
}
```

`payload.room` 为 `BattleRoomView`，按当前连接用户计算 `resultForMe`。

**事件清单：**

| 事件 | 方向 | 触发 | `payload` 要点 |
|---|---|---|---|
| `battle.snapshot` | S→C | 连接/重连 | `room` 完整房间快照 |
| `battle.player.joined` | S→C | 对手加入 | `roomId`、`opponent: UserBrief` |
| `battle.player.connection` | S→C | 参与者上线/离线 | `userId`、`online`、`roomStatus` |
| `battle.player.ready` | S→C | 任一方准备变化 | `userId`、`ready`、`roomStatus` |
| `battle.started` | S→C | 房主开始成功 | `problem: ProblemSummary`、`startedAt`、`endsAt` |
| `battle.submission.updated` | S→C | 任一方提交状态变化 | `userId`、`submissionId`、`status`、`verdict`、`score`、`judgedAt`；不含代码 |
| `battle.ended` | S→C | 先 AC/超时/认输/断线/房主取消 | `resultForMe`（取消时为 null）、`endReason`、`endedAt` |
| `battle.ping` | S→C | 每 5 秒 | `serverTime`；客户端回 `battle.pong` |
| `battle.error` | S→C | 非法状态/内部错误 | `code`、`message` |

**心跳与断线：**

- 服务端每 5 秒发送 `battle.ping`；客户端必须在 5 秒内回 `battle.pong`。
- 连续 2 次未收到 `battle.pong`（约 10 秒）视为断线；`ongoing` 中断线方判负，`endReason=disconnect`。
- 等待/准备阶段断线不判负，只关闭连接并广播离线状态；断线方可通过 `BAT-04` 重新获取房间快照并重连 `WS-01`，本版不提供自动重连，需前端主动重试。
- WebSocket 关闭码：`4401` 未认证、`4404` 房间不存在或当前用户非参与者、`4409` 房间已结束。

| 字段 | 类型 | 必填 | 约束 |

1. 随机模式不得携带 LLM 服务商/凭证字段；两种 LLM 模式必须使用当前用户有效凭证。

5. 创建任务时复检凭证可用性；失败不创建任务。
6. 任务异步执行；返回 `202` 与任务 ID，前端轮询 `DG-04`。
7. 失败即终止，不自动重试；更新凭证后可重新提交新任务，不提供“原地重试”接口。
8. 服务端将题面、数据范围、特殊要求发送给所选 LLM 服务商；不得发送 API Key 以外的敏感数据。

| 规则 | API 落点 |

### 8.3 并发与幂等检查

| 场景 | 接口行为 |
|---|---|
| 重复提交 OJ | 每次创建新提交；首次 AC 由唯一约束幂等 |
| 客观题重复提交 | 每次创建新提交；错题本按用户+题聚合 |
| 阶段完成重复 PUT | 幂等，更新 `completedAt` |
| 外链完成重复 PUT | 幂等 |
| 手动申报重复 PUT | 覆盖当前周记录，不累加 |
| LLM 任务并发创建 | 数据库生成列唯一约束 + Redis 锁；返回 409 |
| 双方同时 AC | `battle_room` 条件更新；只有第一个结果生效 |
| CF 刷新重复触发 | 执行中返回 409 |
| 房间准备重复设置 | 幂等 |
| 删除不存在的本人资源 | 404；重复删除错题本/退出登录按幂等处理 |

### 8.4 已知限制与风险

1. 外链题 CF 自动完成缺少题目级 AC 数据源，已确认本版仅支持手动完成（见 9.1 Q-API-01）。
2. 首页由多个接口组合，首屏请求数较多；首期规模可接受，不做聚合接口。
3. 榜单实时派生，数据量大时查询变慢；首期以索引和分页兜底，后续可加短期缓存。
4. 简答题参考答案在提交完成后返回，可能被用于再次提交刷分；PRD 未定义防刷规则，本期按“允许重新提交”处理。
5. 管理后台不提供选手代码查看，若后续需要需单独评估隐私与权限。
6. 对战断线以 WebSocket 心跳判定，弱网误判风险由 5s/2 次阈值控制，阈值可配置。
7. 本文字段类型为接口契约，具体 Java DTO/TypeScript 类型在实现阶段生成；不得据实现反改本文而不更新文档。

## 10. 当前快照

### 10.1 已确认结论（沿用前序阶段）

- 9 个模块、24 张表、榜单派生、首次 AC 唯一事实、对战提交同口径。
- 前后台独立会话 + CSRF；后台角色固定为 `super_admin` / `content_operator`。
- LLM 凭证每人一份、加密保存、不回显、任务中不可替换；单人最多 1 个进行中 LLM 任务。
- 文件保留 7 天，只清理文件、保留任务记录。
- 时间 UTC 存储；周榜按北京时间自然周；手动申报同周覆盖。

### 10.2 本阶段新增结论

- 统一响应包络、字符串 ID、`camelCase` 字段、1 起始分页。
- 选手端 `/api/v1` 与后台 `/api/v1/admin` 分离；后台接口逐项标注运营/超管权限。
- OJ/简答异步、客观题同步；造数据 202 + 轮询；CF 刷新异步。
- CF 外链题仅手动标记完成；选手端不提供 CF 刷新入口。
- 管理员账号仅可创建 `content_operator`，重置密码由超管直接设置新密码。
- 手动申报仅当前周可改删；简答评分要点按分值求和，总和等于满分。
- 路线发布不额外校验阶段数量；对战不限制同一用户并行房间数。
- 对战状态变更全部走 REST，WebSocket 只做推送与心跳，避免双写。
- 文件下载二进制不套响应包络；生成器代码无任何下载接口。
- 首页不做专用聚合接口，由现有接口组合。
- 头像统一走文件上传：选手端 ME-04、后台 ADM-UPLOAD-01；服务端按魔数校验 JPG/PNG、≤ 2MB、宽高 ≤ 4096px，返回站内路径，由 MEDIA-01 公开只读。
- 后台用户写操作仅超管：新增、批量启停用、批量逻辑删除、重置密码、更换头像；内容运营只读。删除为逻辑删除，历史数据保留。

Q-API-01～Q-API-08 均已确认。整体评审中的 V-01（简答题满分固定 100、及格线 60）与 V-02（CF 当前有效绑定优先，无有效绑定时取最近解绑记录）已由用户确认；V-03（PRD 外链题自动完成表述）按建议保持现有设计，后续单独回写 PRD。首期实现已按本文落地，Controller 实际契约与接口索引一致；剩余事项为部署与运维验证，不涉及接口契约变更。
