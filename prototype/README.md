# 题阵 · 交互原型

基于 `docs/PRD-v0.9.md`（v0.9.1 内容）制作的纯前端可交互原型，用于验证交互与页面结构。

> 本目录不包含服务端逻辑。首期实际实现位于 `frontend/` 与 `backend/`：判题接入 go-judge、CF 使用真实公开 API、LLM 使用真实服务；原型中的外部服务仍以本地模拟规则演示。

## 运行

直接双击 `index.html` 即可打开；或在本目录启动静态服务器：

```bash
python -m http.server 8080
```

然后访问 <http://localhost:8080>。

建议使用 Chrome / Edge 等现代浏览器，桌面宽度体验最佳，页面同时适配移动端。

## 视觉与交互语言

- 底色为奶油 / 米白，点缀低饱和的蜜桃粉、薄荷绿、鹅黄与浅天蓝；不使用蓝紫渐变主色。
- 标题与关键数字优先使用圆润字体霞鹜文楷（LXGW WenKai，CDN 加载失败时回退到系统圆体 / 无衬线字体）；按钮、卡片、标签统一使用大圆角。
- 轻量微动效：按钮 hover 轻微回弹、卡片 hover 上浮、页面加载时元素错落入场，单次 150–300ms；代码输入、提交判定、造数据提交等核心操作区不做位移动效，并遵循系统「减少动态效果」设置。

## 原型中的模拟规则

- **演示判题**：不执行真实代码。代码中包含 `// wa`、`// tle`、`compile_error`、`runtime_error`、`segfault` 等标记会返回对应结果，其余情况返回 AC。
- **首次 AC**：同一用户对同一题只有第一次 AC 计入站内周榜与总榜；重复 AC 会写入提交记录但不重复加分。
- **榜单**：分「周榜 / 总榜」双页签，默认周榜。周榜按自然周统计站内本周首次 AC + CF 数据 + 其他平台本周手动申报；总榜按全部历史累计站内首次 AC + CF 历史累计 + 手动申报历史累计。手动申报标记为「未校验」，总榜只读；两种榜单总分相同均按站内过题数降序，仍相同则并列。首页摘要卡片与后台榜单管理同步支持切换。
- **CF 绑定**：仅支持预置账号白名单（如 `demo_cf`、`tourist`、`Benq`、`neal`、`ecnerwala`），一个选手只能绑定一个 CF 账号。原型用白名单模拟真实 API 校验；后台「刷新 CF 数据」按钮仅超级管理员可见。
- **头像上传**：编辑资料支持点击选择或拖拽 JPG / PNG，大小不超过 2MB；原型在本地压缩为 256px 后保存到 `localStorage`，未上传时使用昵称首字。
- **1v1 对战**：邀请码房间，双方就位后房主开始；30 分钟倒计时，先 AC 者胜，超时平局，主动退出或断线判负。等待页提供「模拟对手加入」等演示控制。
- **路线课程**：每个阶段可关联多门 B 站视频课程，路线详情与阶段详情都会展示；点击在新标签页打开 B 站。课程观看不计入阶段进度，阶段仍由「标记完成」控制。后台可在阶段编辑中增删改课程，链接保存时自动规范化为 `https://www.bilibili.com/video/BV...`，不接受只填 BV 号。
- **简答题 AI 判分**：不调用真实模型，按答案长度与关键词覆盖度模拟 0–100 分，返回评语并展示参考答案与评分要点。低于 60 分记为未通过并加入错题本；简答题不计入周榜，可修改答案后重新提交。答案过短或缺少关键术语会得到低分，填写「模拟失败」可演示判分服务异常。
- **AI 造数据**：支持「随机生成」「LLM 构造」「LLM 直接生成数据」三种模式，均产出约 10 组数据 + std 输出。LLM 构造模式模拟「LLM 构造中 → 生成中 → 完成」，生成器代码不展示；LLM 直接生成模式模拟「LLM 生成数据中 → 格式/范围校验 → 运行 std → 完成」，不生成构造器。std 中加入 `// TLE` 或任务名包含「失败」可演示失败终止；LLM 模式下特殊要求填写「模拟失败」可分别演示构造器校验失败或数据校验失败，填写「模拟 Key 失效」可演示执行时凭证失效、任务终止且不自动重试。生成文件可逐组或打包下载（打包为模拟文本文件）。
- **LLM 凭证**：LLM 造数据使用选手自己的 API Key，需先在个人中心配置服务商（预置 DeepSeek / 通义千问 / 智谱 AI / OpenAI）与 Key，模型选填；每位选手仅保留一份凭证，页面只展示脱敏尾号。保存时模拟校验：Key 少于 8 个字符、包含 `invalid`（如 `invalid-key`）会被拒绝保存；包含 `expired` 或「欠费」同样视为校验失败。未配置有效凭证时两种 LLM 模式禁用；同一时间最多 1 个进行中的 LLM 任务，任务进行中不能替换或删除凭证。简答题 AI 判分不使用该凭证。
- **后台操作**：新增 / 编辑 / 删除均写入演示数据与操作日志；被路线引用的题目会阻止物理删除，提示先下架。用户启禁用、CF 刷新与角色管理仅超级管理员可操作。

## 与首期实现的差异

- 原型只覆盖主要交互路径；首期实现还包含后台新增用户、批量启停用、批量逻辑删除、重置密码、更换头像等接口。
- 原型不执行真实代码、不调用真实 CF / LLM；首期实现分别接入 go-judge、Codeforces 公开 API 与 OpenAI 兼容服务。
- 原型头像保存在浏览器本地；首期实现由服务端校验并落盘，通过 `/api/v1/media/avatar/**` 公开读取。

所有演示数据保存在浏览器 `localStorage` 的 `tizhen_proto_v1` 键下，不上传任何服务器。原型数据结构升级后，旧版本本地数据会按种子版本自动重置。
